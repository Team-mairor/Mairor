# backend 작업 규칙

## Swagger(API 문서) 작성 양식

모든 API 는 아래 양식을 지킨다. 새 API 를 만들면 컨트롤러에 같이 쓰고, `OpenApiDocsTest` 가 빠진 곳을 잡아낸다.

- **Tag (컨트롤러)**: 한국어 이름 + 한 줄 설명. 영문 기본값(`xxx-controller`)이 남으면 안 된다.
  - 예: `@Tag(name = "회원가입", description = "가입 가능한 이메일 확인과 자체 회원가입.")`
- **summary (메서드)**: 한국어 명사구, 12자 안팎. 예: `로그인`, `내 로그인 기기 목록`, `인증번호 발송`
- **description (메서드)**: 첫 문장은 "무엇을 하는지" 한 문장. 이어서 불릿 **최대 3개**로 주의점·규칙만 쓴다.
  - Swagger 가 이미 보여 주는 것(자물쇠 인증 표시, 필드 목록)은 되풀이하지 않는다.
  - 설정값 숫자(잠금 횟수·시간 등)는 쓰지 않는다. 서버 설정이라 바뀐다.
- **응답**: `@ApiResponse(responseCode, description)` 한 줄씩. 오류는 `원인. (에러코드)` 형식으로 실제 코드를 괄호에 쓴다.
  - 공통 오류(401/403/404)는 `AuthApiDocs` 의 메타 어노테이션을 쓴다. 예시 JSON 은 성공 응답과 로그인처럼 형태가 헷갈리는 곳에만 단다.
- **DTO 필드**: `@Schema(description, example)` 에 쓸 수 있는 값을 넣는다. `string` 이 기본값으로 남으면 안 된다.
- 인증이 필요하면 `security = @SecurityRequirement(...)` 로 표시한다(변경 요청은 `sessionCookie` + `csrfToken`).
- 말투는 "~한다" 체로 통일한다.

## 작업 방식

- 한 단계씩 진행하고, 단계가 끝나면 한 일과 커밋 메시지를 알려 준 뒤 승인받고 커밋한다. 푸시는 사용자가 한다.
- 커밋 메시지는 `type(scope): 한국어 요약` 형식이다.
