# 화면 흐름과 상태

실행 시작부터 리포트까지 화면이 어떤 상태를 쓰고 언제 무엇을 저장하는지 적는다. 카메라·얼굴 추적·가이드 그리기는 [FACE_CAMERA_OVERLAY.md](FACE_CAMERA_OVERLAY.md), API 호출 규칙은 [API_CLIENT.md](API_CLIENT.md)에 있다.

## BE API를 쓰는 범위

- 회원: 로그인·가입·비밀번호 재설정·로그아웃
- 파우치: 분류·제품 찾기·내 파우치 목록·상세·등록·수정·삭제 (API-POUCH-001~008)
- 영상: 검색·선택·인기·분석 요청·내 분석 목록 (`/v1/videos/…`, `/v1/users/me/analysis-jobs`)
- 분석: 상태(`GET /v1/users/me/analysis-jobs/{jobId}`와 SSE `…/events`)·재시도(`POST …/{jobId}/retry`)
- 가이드: 조회(`GET /v1/guides/{guideId}`)
- 가이드 실행: 얼굴 등록, 실행 시작·사진 동의·중도 종료·완료 (`/v1/users/me/executions/…`), 단계 사진 업로드
- 리포트: 목록·상세·삭제 (`/v1/users/me/history-records`)

홈·파우치·리포트는 로그인한 계정의 API 응답을 보여 준다. 비로그인 상태에서 샘플 사용자의 파우치·리포트는 보여 주지 않는다. 온보딩의 흐린 파우치 보드는 실제 계정 데이터가 아닌 예시 화면이다.

## 세션 상태

상태를 바뀌는 이유별로 나눠 `domain/session`에 둔다. 화면은 필요한 상태만 훅으로 읽어, 한 상태가 바뀌어도 다른 상태만 읽는 화면은 다시 그려지지 않는다.

| 상태      | 훅                 | 저장 키                   | 내용                                     |
| --------- | ------------------ | ------------------------- | ---------------------------------------- |
| 로그인    | `useAuth`          | `mairor-auth-v1`          | 로그인 여부·이메일·닉네임·세션 만료 안내 |
| 기기 설정 | `useDevice`        | `mairor-device-v1`        | 온보딩·튜토리얼 안내를 본 적 있음        |
| 파우치    | `useMyPouch`       | `mairor-pouch-v1`         | 서버에서 받은 내 파우치 목록             |
| 리포트    | `useStoredReports` | `mairor-reports-v1`       | 완료 리포트 요약                         |
| 검수 대기 | `usePendingGuide`  | `mairor-pending-guide-v1` | 홈에 띄우는 영상 검수 카드               |
| 실행      | `useRun`           | 없음(메모리)              | 지금 진행 중인 실행. 저장하지 않는다     |

- 로그인·로그아웃·세션 만료와 저장값·세션 확인 상태는 `useSessionActions`가 맡는다
- 로그아웃·만료 때는 파우치·리포트·실행을 비운다. 다른 계정으로 로그인해도 이전 계정의 파우치·리포트는 쓰지 않는다
- 옛 저장 키(`mairor-session-v2`)는 첫 로드 때 위 키로 나눠 옮기고 지운다. 새 키가 이미 있으면 덮어쓰지 않고, 저장돼 있던 옛 `run`은 버린다
- 여러 상태를 한꺼번에 보는 `useSession`은 테스트와 개발용 화면(`dev-nav`)만 쓴다
- `SessionProvider`의 `seed`는 테스트에서 초기 파우치·리포트를 넣을 때만 쓴다

## 실행 시작과 로딩

- `/loading?guideId=<UUID>`에서 시작한 실행은 화면을 옮겨도 같은 조회 응답의 단계·설명·영상 제품·영역을 쓴다
- `/loading?jobId=<UUID>`면 그 분석 작업의 진행 상태를 받는다. 재시도할 수 있는 실패면 "다시 시도"를 띄운다
- 유효한 jobId나 가이드 실행이 없으면 진행 화면을 띄우지 않고 영상 선택(`/select`)으로 보낸다
- `/tutorial?guideId=<UUID>`로 바로 들어오면 새 실행 준비(`/loading`)로 보낸다
- 실행 경로(`/loading`·`/check`·`/tutorial`·`/done`)는 실행을 먼저 시작해야 열린다. 주소만 입력하면 영상 입력으로 간다

## 얼굴 등록

로딩 화면 모달에서 실시간으로 4가지를 판정하고, 4개를 1.5초 유지하면 정면 1장을 찍는다.

| 조건 | 판정                                            |
| ---- | ----------------------------------------------- |
| 조명 | 얼굴 가운데 밝기                                |
| 거리 | 얼굴 폭 비율과 가운데 위치                      |
| 정면 | yaw·pitch·roll                                  |
| 가림 | 핵심 부위와 얼굴 윤곽이 화면 안에 정면으로 보임 |

- 찍는 순간 눈을 감았으면 버리고 다시 잰다
- 표정은 판정하지 않고 안내 문구로만 요청한다. 손 가림은 아직 판정하지 못한다
- 기준값은 `vision/face/face-register.ts`에 있다. 밝기·좌우·기울기는 갤럭시탭 S6 Lite에서 재서 정했고, 거리·가운데·위아래는 하프미러 실측으로 확정한다
- 미러필름 모드에서는 위치를 거울에 비친 얼굴 기준으로 보고, 가림은 부위 대신 추적이 안정적인지(`tracking`)만 본다. 자세한 것은 [하프미러 좌표 보정](FACE_CAMERA_OVERLAY.md#하프미러-좌표-보정)
- 실제 가이드 실행은 찍은 사진을 서버에 등록하고(`POST /v1/users/me/face-registrations`, 받은 ID가 있어야 등록됨), 화면용 사진은 메모리에 둔다. 서버 연동은 [API_CLIENT.md](API_CLIENT.md#얼굴-등록)
- 등록에 쓴 카메라는 제품 확인에서 그대로 이어 쓴다. 등록 전에 '나중에'를 누르면 카메라를 끈다

## 부위 묶음

실제 가이드는 단계가 수십 개로 잘게 나뉜다. 튜토리얼은 영상 순서를 바꾸지 않고, 연속해서 같은 영상 속 제품을 쓰는 단계를 한 묶음으로 본다 (`domain/guide/step-group.ts`). 영상에서 제품 정보를 찾지 못한 단계는 묶지 않고 따로 둔다.

- 튜토리얼 상단 바는 묶음 하나가 한 칸이고, 단계 제목 옆에 묶음 안 위치("피부 2/5")를 띄운다
- 묶음 이름은 첫 단계의 매칭 카테고리(피부·눈·눈썹·볼·입술)로 정한다. 카테고리를 모르면 단계 이름을 쓴다
- 묶음 안 다음 단계는 준비 카드 없이 이어서 시작하고, 제목·할 일을 잠깐 강조한다. 앞 단계와 제품이 다르면 제품도 알린다

## 단계 사진

### 촬영

- 튜토리얼 안내에서 사진 저장에 동의해야 시작할 수 있다. 동의 없이 `/tutorial`에 들어오면 동의 카드로 보낸다
- 묶음의 끝에서 찍는다 (제품 없는 단계·생략한 단계 포함)
- 가이드·UI 없는 카메라 프레임을 화면에서 보던 방향(좌우 반전)으로 찍는다
- 촬영 대기·판정은 `features/tutorial/use-step-shot.ts`(`useStepShot`)에 있다
- 마지막 단계 사진은 리포트에 통째로 보여 주므로 턱까지 얼굴 전체가 들어와야 찍는다. 찍은 뒤 사진을 보여 주어 다시 찍거나 그 사진으로 완성하게 한다 (`useFinalReview`)
- 미러필름은 카메라 영상을 숨기므로 마지막 사진을 찍는 동안만 위쪽에 카메라 화면(`SelfiePreview`)을 띄운다. 촬영하기를 눌러야 3초 카운트다운을 시작한다 (`useFinalCountdown`)

### 언제 찍고 언제 다시 찍나

- 얼굴 점이 0.3초 멈췄을 때 찍는다. 2.5초가 지나면 그냥 찍는다
- 지금 묶음의 부위가 화면 밖이면 보일 때까지 기다리며 안내한다. 기다리는 동안 '이전' 버튼은 촬영 취소다
- 찍는 순간 아래 중 하나면 찍지 않고 '다시 찍기'로 돌린다
  - 추적이 끊김
  - 마지막 실제 검출(`detectedAt`)이 `FRAME_STALE_MS`보다 오래됨
  - 부위가 화면 밖
- 영역을 찾지 못한 단계는 촬영 판정과 확대에 화장 종류의 기본 가이드 부위를 쓴다. 기본 가이드를 못 불러오면 찍지 않고 '다시 불러오기'로 다시 받는다

### 저장과 업로드

- 사진은 얼굴 전체로 두고, 묶음 안 단계 부위를 모두 감싼 정사각형 위치(`box`)를 함께 저장한다. 리포트 단계 칸에서는 그 부위만 확대한다
- 사진은 실행 id와 묶음 마지막 단계 id(`stepId`)로 찾는다
- 실제 가이드 실행은 `PUT /v1/users/me/executions/{executionId}/steps/{stepId}/photo`(API-GUIDE-005)로 업로드한다
  - 올리는 동안 다음·이전을 막는다
  - 30초 안에 답이 없으면 끊고 실패 이유와 함께 다시 찍게 한다
  - 사진 동의가 없으면 동의 카드로 보낸다
- 화면·리포트용 사본은 `domain/session/step-photos.ts`의 메모리에 JPEG data URL로 둔다

### 지우는 때

- 동의 화면에서 다시 시작하면 촬영 기록과 남은 사진을 함께 비운다
- 완료 기록을 남긴 실행의 사진만 남긴다. 기록 없이 끝나거나 무효가 된 실행의 사진은 실행이 바뀔 때(`RunProvider`) 지운다
- 리포트를 지우면 그 실행의 사진도 지운다

## 리포트

- 리포트 화면(홈 최근 리포트·목록·상세)은 로그인한 계정의 서버 기록을 읽는다
- 상단 바·완성 화면은 촬영 기록(`captures`)이 아니라 실제로 남은 사진으로 판단한다
- 남은 사진이 있으면 띄운다. 없으면 아래를 나눠 보여 준다
  - 찍지 않은 단계: '미촬영'
  - 찍었지만 사진이 없는 단계: '사진 없음'·'사진을 불러오지 못했어요'

## 로그인과 파우치

- 로그인했으면 홈·내 파우치가 서버 파우치를 받아 `useMyPouch`의 목록을 바꾸고(`usePouchSync`), 다른 화면도 이 목록을 쓴다
- 로그인 전에는 파우치를 보여 주지 않는다. 수정 시트는 저장·삭제 없이 로그인 안내만 띄운다
- 파우치 일러스트는 종류 코드로 고른다 (`domain/pouch/catalog.ts`의 `TYPE_ILL`). 모르는 코드는 카테고리 기본 그림이다
- 세션 확인·만료·로그아웃 때 파우치 처리는 [API_CLIENT.md](API_CLIENT.md#세션)

## 개발·테스트용 mock

`NEXT_PUBLIC_API_MOCK=success`와 fixture는 개발·테스트에서 API 응답을 확인하는 용도다. 제품 화면은 mock 응답으로 실행을 시작하지 않는다.

- 모의 가이드의 단계와 영상 제품은 AI 샘플 영상(`ai/samples/local_01`)의 가이드 입력을 옮긴 `mocks/mock-guide.ts`에서 만든다
- 가이드 대상이 아닌 단계(스킨케어 등)는 뺀다. 단계 수가 영상마다 다르므로 화면은 목록 길이대로 돈다
- 영역은 같은 샘플 영상의 `/fixtures/guide-areas/local_01.json`을 쓴다

모의 가이드 ID (`NEXT_PUBLIC_API_MOCK=success`):

| guideId                                | 내용                                          |
| -------------------------------------- | --------------------------------------------- |
| `a0000000-0000-4000-8000-000000000001` | 샘플 영상 가이드                              |
| `a0000000-0000-4000-8000-000000000002` | 9가지 화장 종류 (마스카라는 설명 없이 요약만) |
| `a0000000-0000-4000-8000-000000000003` | 로그인 필요 (401)                             |
| 그 밖의 ID                             | 404                                           |

## 상태 확인

- 카메라·가이드 상태는 `/debug/tutorial`, `/debug/preview`, `/debug/overlay`와 API 디버그 화면(`/debug/api`)에서 확인한다
- 빈 상태·오류 상태는 컴포넌트에 fixture를 주입하는 테스트로 확인한다
- 홈의 `?empty=1`은 리포트·파우치 빈 상태를 데이터를 지우지 않고 확인한다
