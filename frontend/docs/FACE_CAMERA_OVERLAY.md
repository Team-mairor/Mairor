# 얼굴 추적·카메라·오버레이 모듈 사용법

카메라·얼굴 추적(`features/face`), 화장 레이어(`features/overlay`), 튜토리얼 가이드(`features/guide`)를 화면에서 쓰는 방법과 기기별 측정 결과, 아직 확인하지 못한 것을 적는다. 실행 방법, 확인 화면, 합성·가이드 표현 규칙, API 클라이언트는 [README](../README.md)에 있다.

## 카메라·얼굴 추적

`(live)` 레이아웃의 `CameraProvider`가 카메라와 추적을 한 번만 켠다. 로딩(얼굴 등록) → 미리보기 → 제품 체크 → 튜토리얼은 다시 초기화하지 않고 이어 쓰고, 이 묶음을 떠나면 끈다.

```tsx
// (live)/layout.tsx
<CameraProvider autoStart={false} errorView="none">{children}</CameraProvider>

// (camera)/layout.tsx: 들어오면 켜고, 이미 켜져 있으면 그대로 쓴다
<StartCamera />
```

- `autoStart`: 기본 `true`. 로딩 화면은 얼굴 등록을 시작할 때 `start()`를 직접 부르므로 `false`로 둔다
- `errorView`: `replace`면 오류 시 자식 대신 오류 화면을 보여 준다(확인 화면용). `none`이면 화면이 `error`를 직접 보여 준다(앱 화면)
- 카메라는 640×480(4:3)으로 받아 자르지 않고 전부 보여 준다(`containTransform`)
- 프레임을 받는 곳(`useFaceFrame`·`useFaceRender`)이 하나도 없으면 추적만 쉬고 카메라와 모델은 그대로 둔다

| `useCamera()`               | 내용                                                                              |
| --------------------------- | --------------------------------------------------------------------------------- |
| `status`, `error`           | `idle` · `starting` · `ready` · `error`, 오류 종류는 `CameraError.kind`           |
| `start()`, `stop()`         | 겹쳐 불러도 카메라는 한 번만 연다. 시작 중에 `stop()`하면 늦게 열린 카메라를 끈다 |
| `viewTransform`             | 원본 프레임 → 화면 좌표 변환. 영상 크기를 알기 전에는 `null`                      |
| `showVideo`, `setShowVideo` | 하프미러 앞에서는 영상을 숨기고 가이드만 그린다                                   |
| `setCoverPanel(el)`         | 화면 아래를 덮는 패널. 패널 뒤 부위는 화면 밖으로 판정한다                        |
| `videoRef`                  | 얼굴 등록 사진처럼 영상 프레임이 필요할 때                                        |

`useFaceFrame((frame, stats) => …)`은 실제 추론 결과마다 불린다. 등록·촬영 조건과 화장 합성은 이 관측 결과를 사용한다. `useFaceRender((frame, stats, now) => …)`는 최신 관측을 화면 주사율 콜백에서 전달하며, 튜토리얼 가이드는 여기서 그리기용 좌표만 예측한다.

얼굴 랜드마크와 가장 큰 얼굴 검출은 classic Worker에서 실행한다. 영상은 한 장씩 `ImageBitmap`으로 넘기며 처리 중에는 요청을 쌓지 않는다. Worker·OffscreenCanvas를 사용할 수 없거나 초기화가 실패하면 메인 스레드 추론으로 시작한다. 추적 중 Worker가 오류를 내거나 10초 안에 응답하지 않으면 한 번만 메인 스레드로 바꿔 이어 가고, Worker로 넘길 영상 이미지를 만들지 못한 프레임은 건너뛰고 30번 연속 실패하면 멈추며, 입력 캔버스 준비·결과 변환 오류는 기존처럼 추적을 멈춘다. 메인 스레드로 추론하면 `stats.backend`에 `main`을 표시하고, 추론 중 화면 그리기도 지연될 수 있다. Worker 실행·이미지 전달·연속 GPU 추론은 PC 크롬에서 샘플 이미지로 확인했다. 갤럭시탭 S6의 실행 방식·FPS는 아래에서 기록한다. 움직임 지연은 아직 확인 중이다.

### FaceFrame

| 필드               | 내용                                                                                                                |
| ------------------ | ------------------------------------------------------------------------------------------------------------------- |
| `trackingState`    | `tracking` · `degraded`(불안정, 숨김) · `hold`(짧게 놓침, 직전 결과 복사) · `lost`. 처음 찾기 전에는 frame이 `null` |
| `landmarks`        | 정규화 좌표 0~1, 반전 전 원본 프레임 기준, 좌우는 사용자 신체 기준                                                  |
| `iod`              | 두 홍채 중심 거리(픽셀). 부위 크기·선 두께는 IOD = 1 기준                                                           |
| `pose`             | yaw·pitch·roll(라디안). 사용자 왼쪽으로 돌리면 yaw +, 위를 보면 pitch +                                             |
| `eyes`             | 눈 뜬 정도(0~1), 깜빡임                                                                                             |
| `regions`          | 부위별 중심·너비·높이·각도                                                                                          |
| `regionVisibility` | 부위별 화면 안 비율(`inFrameRatio`, 하단 패널 뒤는 밖), 카메라를 향하는지(`facing`)                                 |
| `detectedAt`       | 마지막 실제 관측 프레임을 추론에 넣은 시각(ms, 메인 스레드 `performance.now()` 기준). `hold`에서는 갱신하지 않음    |
| `usableRegions`    | 핵심 부위가 하나 이상 보이고 연속 관측에서 좌표·크기가 안정적인 부위. 부분 가이드 표시에만 사용                     |

- 화면 좌표: `toScreen(point, frame.imageSize, viewTransform)`. 거울 반전은 여기서 한 번만 한다
- `stats`: FPS와 구간별 처리 시간(`formatTiming`으로 표시), 근접 입력 축소 배율, 추론 실행 위치(`backend`: `worker`·`main`)

### 숨김과 안내

| 판정           | 기준                                                                                |
| -------------- | ----------------------------------------------------------------------------------- |
| 추적 유지      | 핵심 부위(양쪽 눈·입술) 중 2개 이상이 화면 안에 정면으로 보일 때. 아니면 `degraded` |
| 고개 돌림      | yaw 0.6rad(약 35°) 초과면 그 부위는 `facing: false`                                 |
| 부위가 화면 안 | `inFrameRatio` 0.9 이상. 한번 밖으로 본 부위는 0.03 더 들어와야 다시 보임           |
| 너무 멂        | 얼굴 폭 / 영상 폭 0.4 미만. 숨기지 않고 측정만 막는다                               |

- `useTrackingIssue()`: 얼굴 전체에 대한 안내 이유(`lost` · `turned` · `out-of-frame` · `far` · `null`). 튜토리얼은 `useGuideTrackingIssue(step)`로 현재 단계 부위의 안내를 구해 `useLiveState`에 전달하고, 가이드가 없는 단계는 공통 판정을 쓴다. 문구는 `TRACKING_ISSUE_TEXT`
- `isGuideVisible(frame, region)`: 추적이 `tracking`이고 부위가 화면 안에 정면으로 보일 때만 true
- `HoldVisibility`: `hold` 동안 직전 판정을 유지해 깜빡일 때 화장 레이어가 깜빡이지 않게 한다. 대상이 바뀌면 `reset()`. 튜토리얼 가이드는 아래 `GuideVisibility`가 부위별로 같은 일을 한다

튜토리얼은 `GuideVisibility`로 부위별 표시·진하기와 복귀 조건을 공유한다. 얼굴 전체 판정이 `degraded`여도 해당 부위가 `usableRegions`에 있으면 표시할 수 있다. 부위 너비가 3px 이상이고 두 관측 사이 크기 비율이 0.65~1.55, 중심 이동이 IOD 이내여야 한다. 근접 입력 축소 배율이 기준 이상이고 두 관측 간격이 400ms 이내일 때만 판정한다. 이는 형태의 연속성 검사이며 실제 가림이나 정확도를 보증하는 모델 신뢰도는 아니다. 갤럭시탭 S6에서 확인한 범위는 아래 측정 결과에 있다.

- 화면 안 비율은 0.9, 숨긴 뒤 복귀는 0.93을 사용한다. 표시 여부는 예측 좌표로 바꾸지 않는다.
- 먼 쪽 부위는 yaw 0.45~0.75rad에서 옅어지다 숨기며 가까운 쪽은 유지한다. 절댓값 1.05rad 이상에서는 모두 숨긴다. 갤럭시탭 S6에서 아래 측정 결과로 확인했다.
- 얼굴 윤곽 단계는 먼 쪽 절반과 그쪽 도형을 0.17~0.3rad(약 10~17°)에서 숨긴다. 볼 뒤로 넘어간 윤곽이 화면에서는 볼 위에 찍히기 때문이다. 갤탭 S6에서 보고 정했다.
- `hold`에서는 직전에 보이던 부위만 유지하고 위치 예측을 멈춘다. 마지막 실제 검출에서 300ms가 지나면 가이드를 지운다. 관측 시각이 없는 정적 픽스처는 만료시키지 않는다.

## 화장 레이어

```tsx
<MakeupOverlay layersUrl={url} hidden={hide} />
```

- `layersUrl`: AI 파트 미리보기 출력(`layers.json`). 불러오지 못하면 5초마다 다시 시도한다
- `hidden`: 레이어는 두고 그리기만 멈춘다. 다시 보일 때 새로 불러오지 않는다
- `enabled={false}`는 그리기를 끈다(성능 비교용), `showStats`는 처리 시간을 띄운다
- 화장 캔버스는 CSS 픽셀의 절반 해상도로 그린다. 그리는 픽셀이 많을수록 얼굴 검출이 느려지기 때문이다(아래 측정 결과)

## 튜토리얼 가이드

```tsx
const defaults = await loadDefaultGuideSet(); // 9개 부위 기본 가이드
const area = await loadGuideArea(url); // AI 가이드 영역 (shared/guide-area)
const step = resolveSubStep(subStep, defaults); // 하위 단계 → 그릴 단계 (상태별 처리 포함)
const issue = useGuideTrackingIssue(step); // 단계 부위가 잘리거나 돌아간 이유, 정상이면 null
<GuideOverlay step={canRender ? step : null} />;
```

- `resolveSubStep`: `extracted`는 받은 영역, `template`은 `templateId`의 기본 가이드, `notApplicable` · `failed`는 `null`
- `GuideOverlay`는 지금 단계 도형만 그리고, 단계가 바뀌면 직전 숨김 판정을 버린다
- AI 영역 도형은 원래 묶음의 `region`을 유지해, 양쪽 눈 단계에서도 화면 밖·먼 쪽 도형만 따로 숨긴다. 기존 기본 가이드는 메시 UV와 단계 부위로 좌우를 구분한다.
- 가이드 파일(`GuideSet`)을 직접 쓸 때는 `loadGuideSet(url)`. 불러올 때 부위 이름·기준점을 확인하고 쓸 수 없는 단계·도형만 경고 후 뺀다

### 위치 예측과 비교

최근 두 실제 관측의 이동·크기·화면상 회전으로 얼굴 전체의 표시 좌표만 예측한다. 기본 강도는 0.6, 예측 시간 상한은 80ms, 중심 이동 상한은 IOD의 15%다. 크기와 회전 보정도 제한하며 오래된 속도는 점차 줄인다. 정지·방향 반전은 다음 관측에서 반영하고, 추적 상실·단계 전환·해상도 변경 시 이전 속도를 버린다. 미래의 움직임이나 멈춤을 미리 알 수는 없으므로 강도는 실기기 비교로 정한다.

- `/debug/tutorial?stats&prediction=off`: 예측 없이 관측 위치를 주사율 콜백에서 그린다.
- `/debug/tutorial?stats&prediction=0.6`: 기본 예측과 비교한다. 화면 아래 강도 슬라이더는 0~1이다.
- 통계는 추론 FPS·실행 위치, 그리기 FPS, 마지막 관측의 경과 시간, 전체 추적 상태와 부분 추적 허용 부위를 구분한다. 그리기 FPS는 새 얼굴 관측의 빈도가 아니다.
- 머지된 크롭 화면(S15P31A306-381)의 표시 전환·크롭에 연결했다. 크롭 영상도 주사율 콜백으로 그리며, 실제 관측 부위와 크롭의 교집합으로 표시·안내를 판정한다. 고개 돌림에 따른 먼 쪽 숨김은 크롭이 있을 때도 같은 각도로 서서히 적용한다. 갤탭에서 영상/가이드 좌표와 크롭 경계·안내의 일치를 확인한다.

기준 실기기는 갤럭시탭 S6(SM-T860)이다. 아래 항목을 예측 끔/켬으로 비교하고 거리·yaw·추론 FPS·그리기 FPS·어긋남·정지 시 출렁임을 기록한다.

| 상황                                       | 확인할 동작                                     |
| ------------------------------------------ | ----------------------------------------------- |
| 입이 잘리는 눈 근접, 한쪽 눈만 보이는 근접 | 보이는 눈만 유지하고 불안정한 좌표는 숨김       |
| 좌우 회전·표시 경계 왕복                   | 가까운 쪽 유지, 먼 쪽 숨김, 복귀 시 깜빡임 확인 |
| 천천히 이동·빠른 이동·급정지·방향 반전     | 예측 전후 위치 오차와 정지 시 초과 이동 비교    |
| 추적 상실·복귀·단계 변경                   | 오래된 가이드와 속도가 남지 않음                |
| 화면 꺼짐·앱 전환·카메라/해상도 변경       | 이전 추론 응답을 버리고 새 프레임으로 복귀      |

## 얼굴 등록

로딩 화면 모달(`features/loading`)이 `useFaceCheck(enabled)`로 조명·거리·정면·가림 4개를 실시간 판정하고, 1.5초 유지하면 `captureFace(video)`로 정면 1장을 찍는다. 사진은 `saveFacePhoto(runId, blob)`로 이번 실행에만 보관한다(업로드 API 전). 기준값과 판정 방식은 README 폴더 구조 아래 설명과 `face-register.ts`에 있다.

## 측정 결과

갤럭시탭 S6(SM-T860)에서 `/debug/tutorial?stats=1&prediction=off`로 확인한 값: 추론 12~13 FPS, 실행 위치 `worker`, 그리기 60 FPS(사용자 실기기 관찰). 추론 빈도와 화면 갱신 빈도를 각각 나타낸다. 같은 화면에서 예측 강도를 0에서 0.6으로 올려 좌우 이동·급정지를 비교했을 때 가이드가 더 잘 따라왔고, 아주 약한 떨림이 있었으나 앞지름은 느껴지지 않았다(사용자 관찰). 예측 0.6에서 한쪽 눈만 보이는 근접과 좌우 약 30~45° 회전 모두 가이드가 자연스럽게 유지되었다. 얼굴이 1~2초 화면 밖으로 나가면 가이드가 사라지고, 복귀하면 위치에 다시 맞았다(사용자 관찰).

같은 기기에서 예측 0.6으로 다시 확인한 값(통계 1초 간격 기록, 가이드 정렬은 사용자 관찰):

- 아이섀도 단계: 입이 화면 밖이어도 두 눈 가이드가 유지되고, 한쪽 눈이 절반쯤 잘리면 그 눈만 숨는다. 눈 하나만 화면 가운데 오게 다가가면 추적이 유지되지만, 그 눈이 가장자리로 치우치면 얼굴 검출이 끊겨 lost가 된다
- 회전: 약 ±34°까지 두 눈이 보이고, 약 40°부터 먼 쪽 눈만 숨는다. 베이스 단계 윤곽은 약 60°를 넘으면 모두 숨는다
- Worker를 강제로 종료하면 약 10초 뒤 메인 스레드로 넘어가 추적을 이어 간다. 메인 스레드에서는 추론 13~17 FPS, 그리기 35~43 FPS다

아래 표에서 S6 Lite·S24 울트라·PC 웹캠은 Worker·위치 예측 도입 전, 갤럭시탭 S6는 도입 후 측정이다. 기기가 달라 성능 개선 전후로 직접 비교하지 않는다.

| 기기                                       | 결과                                                                                                                                |

- 배치: 세로로 세우고 카메라를 위쪽에 둔다. 손에 들고 평소 거리(얼굴 폭 비율 약 0.6)에서는 아랫입술이 영상 아래 끝에 걸렸지만, 설치 높이에서는 정면 0.82~0.89, 거울 쪽으로 다가가 립을 바르는 자세에서도 0.84~0.95로 영상 안에 있다. 턱 끝은 다가가면 0.96~1.03으로 아래 끝에 걸린다(영상 위 0, 아래 1)
- 추적: 고개를 좌우 약 58°까지 돌려도 놓치지 않고, 약 36°부터 고개 돌림 안내가 뜬다. 얼굴 폭 비율 0.06까지 멀어져도 추적은 유지되고 0.4 미만에서 가까이 오라는 안내가 뜬다
- 가림: 손으로 볼·눈·입을 가려도 상태가 tracking으로 남아 판정하지 못한다
- 얼굴 등록: 손에 들었을 때는 위아래 각도가 정면 기준(약 11°)을 자주 넘어 정면 조건에서 막혔다. 설치 높이에서는 정면 pitch −1~−6°로 기준 안이다
- 하프미러: 필름 너머로 가이드와 얼굴이 모두 잘 보인다

## tutorial 표시 영역 조정

`/debug/tutorial`에서 전체 카메라 영상 위 점선 영역을 이동하고 오른쪽 아래 손잡이로 크기를 조절한다.
레이아웃 기준 800×1200(모든 화면을 그리는 기준 크기, `globals.css` 화면 크기 대응)에서 상단 140px·하단 372px을 비운 800×688 비율을 사용한다.
갤럭시탭 S6의 주소창 있는 크롬(800×1160)은 앱이 0.967배로 줄어 800×688 그대로이고, 전체 화면(800×1280)은 줄지 않고 세로가 80px 늘어 800×768이 된다. 영역 비율은 그 기기의 레이아웃 높이로 계산하므로, 시연하는 화면 방식(크롬·전체 화면)에서 영역을 맞춘다.
`tutorial 비율로 맞추기`로 이 비율을 맞춘 뒤 `크롭 미리보기`로 확인한다. PC 창 크기는 기기 화면을 축소하는 데만 사용한다.
카메라가 준비되기 전에는 영역 조정·미리보기·적용을 할 수 없다. 실제 영상 비율로 영역을 잡으며, 해상도 비율이 바뀌면 영역을 다시 맞춘다.
`tutorial에 적용`하면 같은 브라우저의 실제 tutorial에도 선택한 영역을 사용한다. `초기화`하면 기존 얼굴 맞춤으로 돌아간다.
저장값은 기기·브라우저·접속 주소별이며 다른 포트나 기기로 옮겨지지 않는다.
영상과 가이드는 같은 변환으로 표시하고 얼굴 인식은 원본 영상 전체에서 유지한다.

크롭 밖으로 현재 단계의 표시 부위가 모두 벗어나면 화면 안으로 들어오라는 안내를 표시한다. 일부가 잘렸을 때는 남은 영역을 유지하며, 다시 들어오면 복구한다. 원본 영상의 인식·추적 상태는 변경하지 않는다.
