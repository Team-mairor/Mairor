# 얼굴 추적·카메라·오버레이

카메라·얼굴 추적(`vision/face`), 화장 레이어(`vision/overlay`), 튜토리얼 가이드(`vision/guide`)를 쓸 때 알아야 할 것과 문제가 생겼을 때 볼 곳을 적는다. 확인 화면 사용법과 합성·가이드 표현 규칙도 여기에 있다. 실행 방법과 개발 도구 목록은 [README](../README.md)에 있다.

기준 기기는 갤럭시탭 S6(SM-T860), 크롬, 세로 배치(카메라 위쪽).

## 문제 발생 시

| 증상                                                               | 먼저 볼 것                                                                                                                                                 |
| ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 카메라가 안 켜지고 화면이 계속 기다린다                            | 앱 화면은 `errorView="none"`이라 오류를 직접 보여 줘야 한다. 화면이 `useCamera()`의 `status`·`error`를 읽는지 확인한다                                     |
| 가이드·화장이 안 그려진다                                          | `/debug/tutorial?stats`에서 추적 상태를 본다. `degraded`·`lost`면 아래 「숨김 기준」, 미러필름 화장이면 턱까지 카메라에 들어왔는지(「하프미러 좌표 보정」) |
| 가이드가 부위만 일부 빠진다                                        | 부위가 화면 안 0.9 미만이거나 먼 쪽으로 돌아간 것. 크롭을 저장한 기기면 크롭 밖인지도 본다(미러필름에서는 크롭을 쓰지 않는다)                              |
| 얼굴이 잡히면 FPS가 크게 떨어진다                                  | 화장 그리기의 GPU 작업을 검출 결과 읽기가 기다리는 것이 원인이었다. 화장 캔버스는 절반 해상도로 그린다(`OVERLAY_DPR`)                                      |
| 화장이 볼·눈 위를 덮는다(가림 마스크 없음)                         | 피부 분할이 꺼진 것. 한 번에 150ms 넘게 두 번 연달아 걸리거나 세 번 연달아 실패하면 끄고 가림 없이 그린다(`makeup-overlay.tsx`). 화면에 끈 이유가 뜬다     |
| 손으로 얼굴을 가려도 추적이 그대로다                               | 아직 판정하지 못한다. 손으로 볼·눈·입을 가려도 `tracking`으로 남는다                                                                                       |
| 추론 위치가 `main`으로 바뀌었다                                    | Worker가 오류를 냈거나 10초 넘게 응답하지 않아 메인 스레드로 넘어간 것. 그리기 FPS가 35~43으로 떨어진다                                                    |
| 미러필름에서 가이드가 비친 얼굴과 어긋난다                         | 거울 맞추기(`/mirror-fit`)를 다시 한다. 세로로만 어긋나면 `DEPTH_GAIN`·`DEPTH_TILT`, 가로로 두 장 보이면 두 눈으로 봐서 생기는 시차(하프미러 한계)다       |
| 미러필름에서 「허리를 펴거나 조금 뒤로 물러나 주세요」가 계속 뜬다 | 가이드는 지금 단계 부위, 화장은 턱까지 카메라에 들어와야 그린다. 입술 가운데는 눈–화면 약 30cm, 턱 끝은 약 36cm부터 들어온다                               |
| 빌드는 되는데 정적 내보내기에서 깨진다                             | 렌더 본문에서 `window`·`matchMedia`·`localStorage`를 읽은 곳이 있는지 본다. 이런 값은 effect나 `useSyncExternalStore`로 읽는다                             |

## 카메라·얼굴 추적

`(live)` 레이아웃의 `CameraProvider`가 카메라와 추적을 한 번만 켠다. 로딩(얼굴 등록) → 제품 체크 → 튜토리얼은 다시 켜지 않고 이어 쓰고, 이 묶음을 떠나면 끈다.

```tsx
// (live)/layout.tsx
<CameraProvider autoStart={false} errorView="none">{children}</CameraProvider>

// (camera)/layout.tsx: 들어오면 켜고, 이미 켜져 있으면 그대로 쓴다
<StartCamera />
```

- `errorView`: `replace`는 오류 때 자식 대신 오류 화면(확인 화면용), `none`은 화면이 직접 `error`를 보여 준다(앱 화면)
- 카메라는 640×480(4:3)으로 받아 자르지 않고 전부 보여 준다. 갤럭시탭 S6 세로에서는 480×640으로 들어온다. 1280×720보다 넓게 보이고 빠르다 (fps 3 → 5~7)
- 프레임을 받는 곳이 없으면 추적만 쉬고 카메라와 모델은 그대로 둔다
- 추론은 Worker에서 한다. Worker를 못 쓰면 메인 스레드로 시작하고, 추적 중 실패하면 한 번만 메인 스레드로 바꾼다(`stats.backend`)

| `useCamera()`               | 쓰는 곳                                                               |
| --------------------------- | --------------------------------------------------------------------- |
| `status`, `error`           | 오류 안내. 오류 종류는 `CameraError.kind`                             |
| `start()`, `stop()`         | 겹쳐 불러도 한 번만 연다                                              |
| `viewTransform`             | 원본 프레임 → 화면 좌표. 영상 크기를 알기 전에는 `null`               |
| `showVideo`, `setShowVideo` | 하프미러 앞에서 영상을 숨길 때                                        |
| `setCoverPanel(el)`         | 화면 아래를 덮는 패널. 패널 뒤 부위는 화면 밖으로 본다(미러필름 제외) |
| `videoRef`                  | 얼굴 등록 사진처럼 영상 프레임이 필요할 때                            |

- `useFaceFrame((frame, stats) => …)`: 실제 추론 결과마다 불린다. 등록 판정과 화장 합성이 쓴다
- `useFaceRender((frame, stats, now) => …)`: 최신 결과를 화면 주사율마다 넘긴다. 튜토리얼 가이드가 위치 예측에 쓴다
- 화면 좌표는 `toScreen(point, frame.imageSize, viewTransform)`로 구한다. 거울 반전은 여기서 한 번만 한다

`FaceFrame`에서 자주 보는 값:

| 필드               | 내용                                                                                                        |
| ------------------ | ----------------------------------------------------------------------------------------------------------- |
| `trackingState`    | `tracking` · `degraded`(불안정, 숨김) · `hold`(짧게 놓침, 직전 결과 유지) · `lost`. 처음 찾기 전에는 `null` |
| `landmarks`        | 0~1 정규화, 반전 전 원본 기준, 좌우는 사용자 신체 기준                                                      |
| `iod`              | 두 홍채 거리(px). 선 두께·도형 크기의 기준                                                                  |
| `pose`             | yaw·pitch·roll(rad). 사용자 왼쪽으로 돌리면 yaw +, 위를 보면 pitch +                                        |
| `regionVisibility` | 부위별 화면 안 비율(`inFrameRatio`)과 카메라를 향하는지(`facing`)                                           |
| `usableRegions`    | 얼굴 전체가 `degraded`여도 연속 관측이 안정적인 부위. 부분 가이드 표시에만 쓴다                             |

### 숨김 기준

| 판정           | 기준                                                                                           |
| -------------- | ---------------------------------------------------------------------------------------------- |
| 추적 유지      | 핵심 부위(양쪽 눈·입술) 중 2개 이상이 화면 안에 정면으로 보임. 아니면 `degraded`               |
| 부위가 화면 안 | `inFrameRatio` 0.9 이상. 숨긴 뒤에는 0.93이 되어야 다시 보인다                                 |
| 고개 돌림      | yaw 0.6rad(약 35°) 넘으면 그 부위는 `facing: false`                                            |
| 가이드 먼 쪽   | yaw 0.75rad 넘으면 먼 쪽만, 1.05rad 넘으면 모두 숨긴다                                         |
| 얼굴 가장자리  | 윤곽 단계의 먼 쪽 절반·그쪽 도형과 쉐딩 단계의 볼 가장자리 도형은 0.3rad(약 17°) 넘으면 숨긴다 |
| 너무 멂        | 얼굴 폭 / 영상 폭 0.4 미만. 숨기지 않고 안내만 한다                                            |
| 놓침(`hold`)   | 직전에 보이던 부위만 유지하고, 마지막 검출 300ms 뒤 지운다                                     |

- 안내 이유는 `useTrackingIssue()`(얼굴 전체)와 `useGuideTrackingIssue(step, crop)`(지금 단계 부위)로 구한다. 문구는 `TRACKING_ISSUE_TEXT`
- 화장 레이어는 `HoldVisibility`, 튜토리얼 가이드는 `GuideVisibility`로 깜빡임을 막는다. 단계가 바뀌면 직전 판정을 버린다
- `usableRegions`는 모양이 이어지는지만 본다(부위 폭 3px 이상, 크기 비 0.65~1.55, 중심 이동 IOD 이내, 관측 간격 400ms 이내). 가림이나 정확도를 보증하지 않는다

### 얼굴 추적 확인 화면

`/debug/face`에서 카메라를 켜고 얼굴 추적 결과를 확인한다.

- 랜드마크와 부위(눈·눈썹·입술·볼·윤곽) 표시, 랜드마크 번호 표시
- 추적 상태, FPS, 구간별 처리 시간, 얼굴 방향(yaw·pitch·roll), 눈 뜬 정도, 얼굴 폭 비율
- 카메라·해상도 선택, 노출·화이트밸런스·초점 고정 지원 여부
- 이마 영역 색(Lab)과 흔들림: 카메라 설정과 조명이 색 측정에 충분히 안정적인지 확인
- 회색으로 표시된 부위는 추적이 불안정해 가이드를 보여주지 않는 상태
- 안내: 가이드·화장을 숨긴 이유(얼굴 놓침·고개 돌림·화면 밖으로 잘림)와 너무 먼 경우. 화면에서는 `useTrackingIssue()`로 같은 값을 받아 안내 문구(`TRACKING_ISSUE_TEXT`)를 띄운다
- 튜토리얼은 `useGuideTrackingIssue(step)`로 현재 부위의 표시와 안내를 맞춘다. `/debug/tutorial?stats&prediction=off`와 `?stats&prediction=0.6`으로 예측을 비교하고 강도 슬라이더로 조정한다. 추론 FPS와 그리기 FPS는 별개다. 조건과 실기기 확인 항목은 [얼굴 추적 문서](FACE_CAMERA_OVERLAY.md#위치-예측과-비교)를 참고한다.

## 좌우와 거울 반전

- 좌우는 사용자 신체 기준이다. 반전 전 원본 프레임과 얼굴 메시 UV에서 사용자 오른쪽 부위(`rightEye` 등)는 왼쪽(x < 0.5)에 있다
- 가이드·화장 레이어 좌표(`MeshAnchor`)와 좌우 라벨은 반전 전 기준 그대로 두고 바꾸지 않는다
- 화면에는 실제 얼굴에 매핑한 뒤 거울 반전을 한 번만 적용한다
- 카메라 영상은 `<video>`에 CSS `-scale-x-100`으로 뒤집는다. 캔버스에 직접 그릴 때는 `drawFitted` 또는 크롭 표시용 `CropView`에서 한 번만 뒤집는다
- 크롭 좌표는 거울 방향 기준이다. `CropView`의 영상과 가이드는 같은 `cropTransform`을 쓰며, 가이드 좌표는 `toScreen`에서 반전한다
- 가이드·화장 레이어 캔버스는 CSS로 뒤집지 않고, `toScreen`(`vision/face/view-transform.ts`)에서 x를 `1 - x`로 바꾼다. 캔버스에 CSS 반전을 더하거나 좌표를 미리 뒤집으면 두 번 반전된다
- 확인: `?guides=/fixtures/guides/right-only.json`을 붙이면 가이드가 화면 오른쪽 얼굴에만 보여야 한다 (`/debug/tutorial`, `/debug/overlay`)

## 화장 레이어

```tsx
<MakeupOverlay layersUrl={url} hidden={hide} />
```

- `layersUrl`: AI 화장 레이어 출력(`layers.json`). 못 불러오면 5초마다 다시 시도한다
- `hidden`: 그리기만 멈추고 레이어는 둔다. `enabled={false}`는 성능 비교용으로 그리기를 끈다
- 캔버스는 CSS 픽셀의 절반 해상도로 그린다. 그리는 픽셀이 곧 검출 지연이다

### 화장 레이어 합성

`/debug/preview`는 개발 검증용으로 카메라 영상 위에 화장 레이어(`layers.json`, AI 파트 출력 규격)를 합성한다. `?layers=경로`로 레이어 파일을 바꿔 볼 수 있다. 사용자용 화장 미리보기 화면은 제공하지 않는다.

| 주소 옵션                                | 설명                                                                                                                                          |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `?layers=경로`                           | 레이어 파일 바꾸기                                                                                                                            |
| `?stats`                                 | FPS, 추적 구간별 시간(입력·검출·변환·큰 얼굴·화면·대기), 그리기·피부 분할 시간, 화장 종류별 그리기 시간, 추론 방식 표시                       |
| `?overlay=off`                           | 레이어를 그리지 않음 (추적만 할 때와 성능 비교)                                                                                               |
| `?occlusion=off`                         | 앞머리·손 등 가림을 반영하지 않음 (피부 분할 끔)                                                                                              |
| `?delegate=gpu\|cpu`, `?blendshapes=off` | 얼굴 추적 실행 방식 바꾸기 (기기별 성능 비교, `/debug/face`도 같음). `blendshapes=off`면 눈 감음 판정이 꺼져 "눈 감으면 숨김"이 동작하지 않음 |

- 모양: `polygon`(부위 외곽선, `exclude`로 빼기), `polyline`(`MeshAnchor` 경로), `uvMask`(얼굴 메시 UV 마스크)
- 섞기: `normal` = 피부×(1−a) + 색×a, `multiply` = 피부×(1−a) + 피부×색×a. a = `opacity` × 마스크 값
- `feather`는 가우시안 흐림으로 근사한다 (σ ≈ feather / 4)
- 얼굴 전체 추적 판정으로, 추적이 불안정하거나(`degraded`) 얼굴을 놓치면(`lost`) 그리지 않는다. 레이어 부위가 모두 화면 밖이어도 그리지 않는다. 깜빡임 같은 짧은 놓침(`hold`)은 직전에 보이던 경우에만 유지한다
- 레이어 파일은 불러올 때 `meshVersion`, 부위 이름, 기준점(삼각형 번호·무게중심 합)을 확인하고, 쓸 수 없는 레이어만 경고 후 뺀다. 불러오지 못하면 5초마다 다시 시도한다
- 고개를 돌리면 먼 쪽 화장은 각도와 화면에서 눌린 정도에 따라 서서히 옅어진다
- 파운데이션은 얼굴 메시로 칠하고, 이마는 위로 늘리며 턱선 쪽은 옅게 한다
- 얼굴 피부 분할(`shared/segmentation/`)로 앞머리·손·브러시가 가린 곳에는 칠하지 않는다 (2프레임마다 갱신)
- 섞기 계산에 영상 픽셀이 필요해 영상도 같은 캔버스에 그린다. 영상을 숨기는 하프미러 모드에서는 `multiply`가 의미 없다

`/debug/overlay`에서는 카메라 없이 픽스처 얼굴(`public/fixtures/`) 위에 레이어를 합성해 본다. `?area=경로`를 붙이면 화장 레이어 대신 가이드 영역 파일을 불러와 합성 얼굴 위에 표시한다. 픽스처 설명은 [docs/FIXTURES.md](FIXTURES.md).

## 튜토리얼 가이드

```tsx
const step = resolveSubStep(subStep, defaults, makeup); // extracted는 받은 영역, template은 기본 가이드, 나머지는 null
const issue = useGuideTrackingIssue(step, crop); // 단계 부위가 잘리거나 돌아간 이유, 정상이면 null
<GuideOverlay step={canRender ? step : null} />;
```

- 지금 단계 도형만 그린다. AI 영역 도형은 원래 부위(`region`)를 유지해 화면 밖·먼 쪽 도형만 따로 숨긴다
- 가이드 파일을 직접 쓸 때는 `loadGuideSet(url)`. 쓸 수 없는 단계·도형은 경고 후 뺀다
- 크롭(tutorial 표시 영역)이 있으면 실제 관측 부위와 크롭의 교집합으로 표시·안내를 판정한다

### 가이드 영역과 단계

앱 화면 `/tutorial`은 AI가 넘기는 가이드 영역(`shared/guide-area`, 단계 → 하위 단계 → 부위별 묶음)을 단계 ID로 찾아 지금 단계의 영역을 얼굴 위에 그린다. 실제 가이드 실행은 `/loading?guideId=<UUID>`에서 시작하고, 같은 실행이 가이드 조회 API(`GET /v1/guides/{guideId}`) 응답의 단계별 `subSteps`를 쓴다. 유효한 실제 가이드 실행이 없으면 튜토리얼·제품 확인·완료 화면은 영상 선택으로 돌려보낸다. 실제 가이드 조회가 로딩 중이거나 실패하면 샘플 단계·영역으로 대체하지 않고 각 상태를 안내한다. 샘플 fixture와 API mock은 `/debug`와 테스트에서만 사용한다.

각 단계의 referenceProduct 필드에는 영상 속 제품 원문과 BE의 기존 카탈로그 대조 결과가 들어간다. 대조는 비동기이므로 최초 조회에서는 productId·shadeId가 null일 수 있고, matchStatus에 따라 연결됨·후보·미연결을 구분한다. 여러 색 칸 중 사용한 칸을 특정할 근거가 없으면 제품·호수까지만 연결한다. 이 기능은 카탈로그 제품을 생성하거나 수집하지 않는다.

| 하위 단계 상태             | 화면                                                                                                                             |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `extracted`                | 받은 영역과 시작점·방향 화살표를 그린다. 화살표가 없으면 영역만 그린다. `exclude` 부위는 영역에서 지운다                         |
| `template`                 | `templateId`(화장 종류)의 기본 가이드를 그리고 "기본 위치" 안내를 띄운다. 영역 파일에 없는 단계도 화장 종류의 기본 가이드를 쓴다 |
| `notApplicable` · `failed` | 그리지 않고 설명만 보여 준다. `failed`면 영역을 찾지 못했다고 알린다                                                             |

코 쉐딩 기본 가이드 키(`contourNose`)는 AI가 쉐딩 하위 단계마다 정해 보낸다. FE는 영역 파일에 없는 단계만 단계 이름에 코·콧·노즈가 있는지(코렉터·코랄 제외, AI와 같은 규칙)로 고르고, AI 하위 단계의 키는 바꾸지 않는다. 그래서 코 + 광대 단계의 둘째 하위 단계(`contour`)는 옆광대 가이드로 그린다. 컨실러 단계(베이스·하이라이트)는 영역 없이 `notApplicable`로 온다.

미러필름이 꺼져 있으면 카메라 영상을 보여 주고 영상 속 같은 자리에 그린다(tutorial 크롭이 있으면 크롭한 영상과 가이드를 함께). 켜져 있으면 영상 없이 거울에 비친 얼굴 자리에 가이드만 그린다.

한 단계에 하위 단계가 여러 개면 모든 영역을 한 번에 그리고, 게이지는 단계마다 한 번이다. 게이지 레퍼런스는 가이드 조회 응답의 하위 단계 `gauge`(바른 뒤 색 · 화장 효과 · 진하기, `domain/guide/gauge.ts`) 중 값이 있는 첫 하위 단계의 것을 쓴다. 기준이 없거나 이유(`reason`)가 있거나 화장 효과 크기가 0인 하위 단계는 건너뛰고, 그런 하위 단계뿐이면 또는 제품 없이 진행하기로 한 단계면 게이지를 숨긴다. 모양이 틀린 기준은 그 기준만 버리고 영역은 그린다. 레퍼런스 위치선은 막대 50%이고, 막대는 카메라에서 잰 진하기 비율 × 50이다(아래 「게이지 기준」). 빼는 부위는 그 부위별 묶음의 도형에만 적용하고, 입을 다물 때의 입 안처럼 영역 넓이의 3%보다 작은 구멍은 빼지 않는다.

`/debug/tutorial`은 기본 가이드를 단계마다 넘겨 보고, `?guides=경로`로 가이드 파일, `?area=경로`로 가이드 영역 파일을 하위 단계마다 넘겨 본다 (`?area=/fixtures/guide-areas/sample.json`은 상태 네 가지와 빼는 영역 확인용).

### 그리기 규칙

- 도형: `point`(시작점), `polyline`(경로, `width`는 점선의 점 지름·붓 자국 두께, `brush: true`면 붓 자국), `polygon`(영역), `arrow`(방향). 위치는 `MeshAnchor`
- 지금 단계의 도형만 그린다. 한 단계 안에서 겹쳐도 구분되게 영역은 멈춘 둥근 점선, 경로는 천천히 흐르는 점선, 방향은 실선 화살표, 시작점은 속이 찬 점, 눈썹 결·속눈썹은 끝이 가는 붓 자국(`brush`)으로 그린다
- 하프미러(검은 배경) 위에 흰 선과 옅은 흰 빛만 그린다. 화면이 밝은 곳은 거울 속 얼굴이 흐려지므로 영역을 채우지 않는다
- 하프미러 필름 너머로 보이도록 선·점은 IOD에 맞춰 굵게 그린다
- 아이라인처럼 따라 그리는 것은 경로, 쉐딩·하이라이트처럼 바르는 곳은 영역으로 정의한다. 바른 정도는 채점하지 않는다
- 화장 레이어와 달리 `GuideVisibility`로 부위별로 숨긴다. 얼굴 전체 추적이 `degraded`여도 안정적으로 관측된 부위(`usableRegions`)는 표시하고, 단계를 바꾸면 직전 판정을 버린다. 거울 맞추기 화면과 얼굴 등록 창에 까는 옅은 얼굴 윤곽은 조금만 어긋나도 어색하므로 얼굴 전체 추적이 안정적(`tracking`)일 때만 그린다
- 불러올 때 부위 이름과 기준점을 확인하고, 쓸 수 없는 단계·도형만 경고 후 뺀다

### 원래 눈썹 맞춤

눈썹 단계 가이드를 얼굴 등록 사진의 원래 눈썹에 맞춘다 (`vision/guide/brow-fit.ts`).

- 찾기: 등록 사진을 찍는 순간 랜드마크 눈썹 둘레를 세로줄로 나눠, 줄마다 랜드마크 눈썹 안의 가장 어두운 곳을 중심으로 잡고(이웃 줄의 가운데 값으로 골라 앞머리 가닥에 끌려가지 않게 한다) 그 줄 맨피부와의 밝기 차이가 절반이 되는 곳까지를 눈썹 두께로 본다. 서서히 어두워지는 눈두덩 그림자와 눈썹보다 훨씬 어두운 머리카락은 빠진다. 눈썹 보통 진하기의 절반보다 옅은 줄은 버리고 보통 두께의 1.5배를 넘는 줄은 잘라, 앞머리 아래 눈 안쪽 그림자로 테두리가 꺾여 내려가지 않게 한다. 테두리는 `MeshAnchor`로 등록 사진과 함께 이번 실행 메모리에만 둔다. 사진은 서버로 보내지 않는다. 등록을 마친 뒤 분석이 끝나도 튜토리얼이 저장을 구독해 그때 가이드를 다시 맞춘다
- 기본 가이드: 같은 결 40개를 랜드마크 대신 원래 눈썹의 윗선·아랫선을 따라 다시 그려 산 높이·두께·기울기를 맞춘다. 윗선·아랫선은 3차 곡선으로 다듬어 털 하나하나의 삐죽함은 따라가지 않는다. 찾은 범위 밖은 랜드마크 눈썹 모양을 이어 붙인다
- 영상에서 찾은 영역: 목표 모양은 크리에이터 것이므로 바꾸지 않고, 랜드마크 눈썹(앞머리 0 → 꼬리 1) 좌표에서 원래 눈썹의 앞머리~꼬리로 늘이거나 줄인다. 높이는 그대로다
- 꼬리는 끝으로 갈수록 옅어 찍을 때마다 짧게 잡히므로, 랜드마크 꼬리보다 길게 찾았을 때만 늘린다
- 원래 눈썹을 못 찾았거나(앞머리 가림·어두운 조명·너무 멂) 찾은 길이가 랜드마크 눈썹의 0.6~1.4배를 벗어나는 쪽은 그대로 그린다
- 확인: `/debug/overlay?area=/fixtures/guide-areas/sample.json&step=s7&brows=1`에서 칠한 얼굴로 찾은 눈썹(초록 실선)과 가이드를 본다. 카메라는 `/debug/tutorial?area=/fixtures/guide-areas/sample.json&sub=s7-1`에서 "원래 눈썹 찾기"를 누른다

### 게이지 기준

진하기 게이지는 사용자 캠에서 그 단계 화장이 얼굴 색을 얼마나 바꿨는지 잰다. 바르기 전 색(기준)을 잡는 방법은 AI 규격(`shared/gauge/README.md`, `baseline.v1.json`)을 따르고 계산 코드는 `domain/gauge/`, 카메라에서 읽는 훅은 `features/gauge/`에 있다.

- 칸 색: 프레임을 얼굴 지도(`shared/face-mesh` UV)로 펴 128 × 128칸으로 나누고 칸마다 평균 RGB를 Lab(D65)으로 바꾼다. 칸마다 4 × 4 점을 같은 삼각형의 같은 비율 자리에서 둘레 네 픽셀로 섞어 읽는다(AI는 8 × 8 지도 픽셀). 재는 칸(`cells.measured`)이 아니거나 사진 밖으로 나간 칸은 비운다
- 정면: 카메라 정면이 아니라 그 사람 정면을 쓴다. 같은 카메라 세션은 얼굴 등록에서 좌우 고개 · 기울기 · 눈 뜸(MediaPipe 깜빡임 값)을 지킨 기준 사진 15장의 pitch 가운데 값을 쓴다. 등록 기준을 쓸 수 없는 다른 세션은 준비 카드에서 앞 사진 30장의 pitch 가운데 값을 먼저 정한다. 그 뒤 기준 사진은 정면 pitch ±0.2 안에서만 고른다. 눈 뜸은 AI 규격의 점 6개 비율(세로 ÷ 가로)이 눈 모양에 따라 뜬 눈도 문턱 아래로 읽혀 깜빡임 값으로 판정하고, 점 6개 비율은 `?gauge`에만 띄운다
- 맨얼굴 기준 · 단계 시작 기준: 얼굴 등록에서 같은 카메라 트랙으로 정면 · 눈 뜬 사진 15장을 모아 칸마다 가운데 값으로 만들고, 맨얼굴·흰자 기준과 정면 pitch를 첫 단계에서 그대로 쓴다. 카메라 트랙이 달라졌거나 등록 기준이 없으면 단계 준비 카드에서 15장을 다시 모은다. 15장을 다 모아야 그 단계를 시작할 수 있다. 사진이 1초 넘게 늘지 않으면 「다시 모으기」가 뜨고, 누르면 그 사람 정면과 모으던 사진을 버리고 지금 자세에서 처음부터 다시 모은다(정면을 다시 배우는 8초 동안은 멈춘 것으로 보지 않는다). 준비 카드는 부위 묶음의 첫 단계에만 띄우고, 묶음 둘째 단계부터는 앞 단계에서 「다음」을 누르기 직전 2초 동안 0.2초마다 남긴 사진을 다음 단계 화장 종류와 그 사람 정면 pitch ±0.2로 다시 걸러, 통과한 사진 전부(최대 11장, 준비 카드의 15장보다 적다)로 기준을 잡는다(`next-start.ts`). 3장보다 적거나 그 사람 정면을 아직 못 정했으면 그 단계만 준비 카드를 띄워 모은다. 손이 얼굴을 가린 사진은 아직 거르지 못한다(아래 「측정 불가 · 안정화」). 이전 단계로 돌아갈 때는 다시 모으지 않는다
- 카메라 잠금: 얼굴 등록에서 맨얼굴 기준을 모으기 전에 잠그고 같은 카메라 세션의 튜토리얼까지 유지한다. 다른 세션은 첫 단계 준비 카드에서 기준을 모으기 전에 다시 잠근다. 잠근 뒤 색으로 기준을 잡아야 측정과 카메라 설정이 같다. 튜토리얼을 나갈 때 잠금을 푼다. 노출은 자동일 때 화면 밝기를 재고 ISO 800에서 노출 시간을 바꿔 같은 밝기를 찾는다(`matchExposure`, 100ms까지). 갤럭시탭 S6은 자동 중에 노출 값을 실제와 다르게 알려 줘 알려 준 값으로 고정하면 화면이 어두워진다(밝기 145 → 50). 화이트밸런스는 지원되는 기기에서만 잠금을 시도한다. 갤럭시탭 S6은 색온도를 0으로 알려 주고, 직접 지정해도 화면 색이 바뀌지 않아 자동으로 둔다
- 조명 보정: 바르는 칸과 그 둘레 8칸을 뺀 맨피부 칸의 지금 − 기준 차이를 시그마 10칸 가우스로 흐려 칸마다 조명 변화로 빼고, 가장자리는 반사(`BORDER_REFLECT_101`)다. `scripts/gauge-light-fixture.py`로 만든 OpenCV 결과와 소수 셋째 자리까지 같은지 시험한다
- 흰자 색: 맨얼굴 기준과 같은 사진(맨얼굴 기준을 못 모았으면 눈 화장 단계 전에 처음 다 모은 준비 카드 사진)에서 눈 다각형을 가로 길이의 5% 안쪽으로 줄이고 홍채 둘레의 1.2배를 뺀다. 사진마다 밝기 상위 25%이면서 반사광(채널 하나라도 250 이상)이 아닌 점의 가운데 값을 내고, 유효한 15장의 가운데 값을 최종 흰자로 쓴다. 레퍼런스 흰자(`gauge.white`)와 색을 맞출 때 쓴다
- 게이지 값(`shared/gauge/measure.v1.json`): 0.2초마다 사진을 거르고, 최근 1초 동안 통과한 사진의 칸 색 가운데 값에서 조명 변화를 빼 하위 단계 영역 묶음마다 잰다. 립 · 블러셔 · 섀도 · 쉐딩 · 하이라이트는 공유 규격의 `methods.color.degree`에 따라 흰자로 두 화면 색을 맞추고, 필드가 아직 없으면 기존처럼 밝기와 색을 모두 맞춘다. 눈썹은 자리마다 비율로 맞춘다. 진하기 비율은 사용자 효과를 레퍼런스 효과 방향으로 투영한 길이의 비이고, 좌우 중 작은 쪽을 쓴다. 아이라인은 재지 않는다(`thinArea`)
- 측정 불가 · 안정화(`shared/gauge/stability.v1.json`): 얼굴 없음 · 고개 돌림 · 멂 · 어두움 · 밝음 · 조명 바뀜 · 눈 감음인 사진은 거른다. 가림(`covered`)은 가림 찾기 모델을 아직 붙이지 않아 거르지 않는다. 비율은 지수 평균으로 다듬고, 튜토리얼 게이지는 못 재는 동안에도 마지막 위치를 계속 유지한다. 연해요 · 비슷해요 · 진해요는 경계 여유와 머무는 시간을 두고 바꾼다. 레퍼런스 효과가 작은 하위 단계는 숨긴다(`weakReference`)
- 게이지 안내 창(`domain/gauge/alerts.ts`): 단계를 넘길 때 문구가 「연해요」면 「조금 더 발라 주세요」를 한 단계에 한 번 묻고(「넘어가기」로 넘길 수 있다. 마지막 단계 「완성하기」에서는 묻지 않는다), 막대가 70(레퍼런스의 1.4배) 이상으로 1초 이어지면 「너무 진해요」 창을 띄우고, 막대가 60 아래로 내려오면 저절로 닫는다(「확인했어요」로도 닫을 수 있다). 한 번 알린 뒤에는 막대가 60 아래로 내려왔다가 다시 넘을 때만 다시 띄운다. 못 재는 동안 남은 마지막 값에는 띄우지 않는다. 화면의 막대 · 문구(연해요 · 비슷해요 · 진해요) · 안내 창은 모두 약 3초에 걸쳐 따라가는 다듬은 막대 값(`use-smoothed-gauge.ts`)에서 정한다. 문구 경계는 막대 35 미만 연해요 · 35~55 비슷해요 · 55를 넘으면 바로 진해요이고, 되돌아올 때만 3점 완충을 둔다(화면용 경계라 `shared/gauge` 규격의 문구 경계와 따로 둔다). 트랙에는 목표 구간(35~55)을 연한 띠로 칠하고, 띠 위쪽 가운데에 「목표」 글자를 둔다(목표 눈금선은 없다). 원래 값은 `?gauge`에만 보인다
- 고른 제품(`shared/gauge/substitute.v1.json`): 튜토리얼을 시작할 때 실행 조회로 단계별 고른 제품을 받아, 제품 없이 진행하는 단계는 게이지를 숨긴다. 대체 제품은 색이 레퍼런스와 거의 같으면(near ≤ 1) 레퍼런스 기준으로 진하기와 색감을 견주고, 멀면 제품 색 쪽으로 옮긴 기준으로 진하기만 견준다
- 기준과 측정값은 이번 실행 메모리에만 두고 저장하거나 보내지 않는다
- 확인: `/debug/tutorial`에서 "맨얼굴 기준 잡기"를 누르면 정면 pitch · 모은 사진 수 · 칸 읽는 시간 · 잠금 결과를 띄운다. 튜토리얼 주소에 `?gauge`를 붙이면(개발 도구) 잰 비율 · 막대 · 색감 · 거른 이유 · 흰자 색과 영역 칸 지도를 띄운다

### 위치 예측과 비교

최근 두 관측의 이동·크기·회전으로 표시 좌표만 예측한다. 표시 여부 판정에는 쓰지 않는다. 기본 강도 0.6, 예측 시간 상한 80ms, 중심 이동 상한 IOD의 15%다. 추적 상실·단계 전환·해상도 변경 때 속도를 버린다.

- `/debug/tutorial?stats&prediction=off`와 `?stats&prediction=0.6`으로 비교한다. 아래 슬라이더로 강도를 바꾼다
- 추론 FPS(새 얼굴 관측 빈도)와 그리기 FPS(화면 갱신 빈도)는 다르다

## 하프미러 좌표 보정

미러필름 모드(`<html class="mirror">`)에서는 얼굴 등록 원·튜토리얼 가이드·개발 검증용 화장 레이어를 카메라 영상 위치가 아니라 거울에 비친 얼굴 위치에 그린다. 모두 같은 `halfMirror` 변환을 쓴다.

```ts
const { frame: reflected, view } = halfMirror(frame, mirrorScreen(canvas), loadMirrorFit());
toScreen(reflected.landmarks[i], frame.imageSize, view);
```

알아야 할 원리:

- 화면이 곧 거울면이라 비친 얼굴은 거리와 상관없이 실제 크기의 절반이다. 실제 크기는 두 홍채 거리(IOD)로 잰다
- 코끝·볼처럼 눈과 깊이가 다른 점은 MediaPipe z로 옮긴다. z는 실제보다 크게 나와 0.75만 쓰고(`DEPTH_GAIN`), 눈과의 세로 거리에 따라 −0.3을 더한다(`DEPTH_TILT`). 두 값은 눈–화면 23~32cm의 정답 찍기로 맞췄다
- 피부 분할 가림 마스크는 눈 깊이 변환으로만 옮긴다. 볼·턱처럼 깊이가 다른 곳은 마스크가 조금 어긋날 수 있다
- 크롭은 쓰지 않는다. 하단 패널도 거울이라 패널 뒤 부위를 화면 밖으로 보지 않는다

미러필름에서 달라지는 동작:

- 그리는 조건: 화장하는 거리(눈–화면 약 20cm)에서는 입술·턱이 카메라 밖이라 위치가 추정값이다. 가이드는 일반 모드처럼 지금 단계 부위가 카메라에 들어오면 그리고(눈 단계는 턱이 잘려도 그린다), 화장은 턱까지 얼굴 전체가 들어올 때만 그린다(`trackingIssue`). 입술 가운데는 약 30cm, 턱 끝은 약 36cm부터 들어온다
- 먼 쪽 숨김: 두 눈으로 보면 화면 위 그림이 약 3cm 옆에 하나 더 보인다. 그래서 고개를 약 10° 넘게 돌리면 먼 쪽을 숨기고 약 5° 안으로 돌아오면 다시 그린다(`hiddenSideFor`)
- 얼굴 등록: 위치는 비친 얼굴이 원 가운데에서 원 지름의 15% 안인지(`faceBoxIn`), 거리는 카메라 영상의 얼굴 폭 비율(최소 0.3)로 본다. 가림은 턱이 잘리기 쉬워 부위 대신 추적이 안정적인지(`tracking`)만 본다. 원 안에 카메라 영상을 띄우지 않는다

거울 맞추기(`/mirror-fit`, 홈 오른쪽 위 내 메뉴의 미러필름 토글 아래):

- 주로 쓰는 눈만 뜨고 십자를 두 눈 가운데에, 간격 −·+로 두 원을 눈동자에 맞춰 저장한다. 배율(사용자 IOD)·이동(카메라·뷰포트 위치)·보는 눈을 `localStorage`(`mairor-mirror-fit`)에 둔다. 거리와 상관없어 한 번만 맞추면 된다
- 간격을 한 번이라도 맞추기 전에는 저장할 수 없다. 처음 배율 0.6이 그대로 저장되는 것을 막는다
- 한쪽 눈을 감으면 뜬 눈 기준으로 다시 그린다(`viewingEye`). 그냥 깜빡임은 0.4초 안에 끝나므로 0.4초 넘게 감아야 바꾸고, 두 눈을 뜨면 0.15초 뒤 돌아간다
- 맞춤은 한쪽 눈으로 한다. 두 눈으로 맞추면 시차 때문에 매번 다르게 나온다

갤럭시탭 S6 상수(`half-mirror.ts`):

| 항목                     | 값    | 근거                                      |
| ------------------------ | ----- | ----------------------------------------- |
| 화면 짧은 변             | 142mm | 1600px ÷ 286ppi                           |
| 화면 위 끝 → 전면 카메라 | 7mm   | 자로 잰 값                                |
| 평균 IOD                 | 63mm  | 사람마다 다른 만큼은 맞춤 배율이 메운다   |
| 전면 카메라 가로 화각    | 45°   | 렌즈·센서 크기로 계산. 깊이 보정에만 쓴다 |

- 뷰포트는 화면 폭을 다 쓰고 상태바·주소창만큼 내려와 있다고 본다(`screen.height - innerHeight`). 아래 내비게이션 바가 있으면 그만큼 어긋나고, 맞춤의 이동 보정이 메운다

정답 찍기(`/debug/mirror-trace`, 개발용): 거울에 비친 두 눈동자·코끝·입술 가운데·턱 끝·양쪽 턱 모서리를 S펜으로 찍어 계산 자리와의 차이(mm)를 본다. 기록은 IndexedDB(`mairor-mirror-trace`)에 남고 「내보내기」로 JSON을 받는다. 지금 평균 오차는 부위별 3~5mm이고, 남은 오차는 찍는 손과 자세에서 온다.

## tutorial 표시 영역(크롭) 조정

`/debug/tutorial`에서 점선 영역을 옮기고 오른쪽 아래 손잡이로 크기를 바꾼 뒤 `tutorial에 적용`한다. `초기화`하면 얼굴 맞춤으로 돌아간다.

- 기준 레이아웃 800×1200에서 위 140px·아래 372px을 뺀 800×688 비율이다. 크롬(800×1160)은 그대로 800×688, 전체 화면(800×1280)은 800×768이 되므로 시연할 화면 방식에서 맞춘다
- PC(가로 창 + 마우스)에서는 창 크기와 상관없이 전체 화면과 같은 1280 기준(800×768)으로 잡는다
- 저장값은 기기·브라우저·접속 주소마다 따로다. 다른 포트나 기기로 옮겨지지 않는다
- 카메라가 준비되기 전에는 조정할 수 없고, 영상 비율이 바뀌면 다시 맞춘다
- 표시 부위가 모두 크롭 밖이면 안으로 들어오라는 안내를 띄운다. 추적 상태 자체는 바꾸지 않는다
