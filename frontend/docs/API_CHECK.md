# 화면별 API 대조

화면마다 서버에 필요한 데이터·동작을 API 명세 v2(`docs/references/api-spec.md`)와 BE 구현에 맞춰 본 결과다. 지금 화면은 API 대신 `lib/mock-data.ts`, `lib/mock-guide.ts`, `features/session`(브라우저 저장), 타이머로 흉내 낸다.

- BE에 구현된 API는 회원(`users`)과 `GET /health`뿐이다. 회원 API는 Google 로그인(USERS-006·007)을 빼고 명세와 같다
- 나머지 도메인(영상·분석·얼굴 등록·파우치·추천·실행·리포트)은 명세만 있고 구현이 없다
- 기준 문서는 BE 개발 서버의 Swagger(`/swagger-ui`, `/v3/api-docs`)다. 명세와 다르면 Swagger를 따른다

## 명세 문서 자체의 문제

- 개수: "현행 API 44개"인데 표는 46행이다. 신규 API 블록 제목도 11개인데 내용은 14개다
- 같은 개념에 다른 이름: `verificationToken`/`emailVerificationToken`, `enabled`/`photoConsent`, `result`/`matchingResult`, `title`/`videoTitle`, `createdAt`/`requestedAt`, `jobId`/`analysisJobId`
- 공통 규칙과 다른 곳: 생성인데 200(VIDEO-001, GUIDE-005), CSRF 표기가 빠진 변경 요청(CAMERA-001·003, VIDEO-006), 429인데 Retry-After 없음(USERS-009·013 ATTEMPTS_EXCEEDED)

## FE에서 할 일

- 회원 화면을 뺀 나머지 화면은 BE 구현에 맞춰 연결한다
- 가이드 영역 형식은 AI 파트가 BE에 이미 요청했다 ([요청 문서](../../docs/requests/2026-10-28-hyeonsoo-jungyoon-api-v2-application.md))
- 미리보기 레이어 전달 경로, 리포트 상세 필드, 매칭 위치는 해당 API를 구현할 때 BE와 정한다
