# 화면별 API 대조

화면마다 서버에 필요한 데이터·동작을 API 명세 v2(`docs/references/api-spec.md`)와 BE 구현에 맞춰 본 결과다. 지금 화면은 API 대신 `mocks/mock-data.ts`, `mocks/mock-guide.ts`, `features/session`(브라우저 저장), 타이머로 흉내 낸다.

- BE에 구현된 API는 회원(`users`)과 `GET /health`뿐이다. 회원 API는 Google 로그인(USERS-006·007)을 빼고 명세와 같다
- 나머지 도메인(영상·분석·얼굴 등록·파우치·추천·실행·리포트)은 명세만 있고 구현이 없다
- 기준 문서는 BE 개발 서버의 Swagger(`/swagger-ui`, `/v3/api-docs`)다. 명세와 다르면 Swagger를 따른다

## 가이드 조회 모의 응답

`NEXT_PUBLIC_API_MOCK=success`로 개발 서버를 띄우면 `GET /v1/guides/{guideId}`가 `mocks/mock-guide-api.ts`의 모의 가이드로 답한다. 목표 색은 실제처럼 null이다.

| guideId                                | 내용                                                                                             |
| -------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `a0000000-0000-4000-8000-000000000001` | 샘플 영상(AI 샘플 local_01). 19단계 중 GUIDE 13단계, 영역은 `fixtures/guide-areas/local_01.json` |
| `a0000000-0000-4000-8000-000000000002` | 화장 종류 9가지를 한 단계씩 (기본 가이드). 샘플 영상에 없는 눈썹까지 확인                        |

영상 검색(`GET /v1/videos/search`)은 검색어와 상관없이 두 영상을 주고, 첫 영상이 위 `…0001` 가이드와 이어진다. 영상 선택(`POST /v1/videos`)은 요청 본문을 보지 않아 어느 영상이든 가이드가 있는 영상으로 답한다. `error` 시나리오는 검색 503 `VIDEO_SEARCH_UNAVAILABLE`, 선택 409 `VIDEO_UNSUPPORTED_FOR_ANALYSIS`다.

## 명세 문서 자체의 문제

- 개수: "현행 API 44개"인데 표는 46행이다. 신규 API 블록 제목도 11개인데 내용은 14개다
- 같은 개념에 다른 이름: `verificationToken`/`emailVerificationToken`, `enabled`/`photoConsent`, `result`/`matchingResult`, `title`/`videoTitle`, `createdAt`/`requestedAt`, `jobId`/`analysisJobId`
- 공통 규칙과 다른 곳: 생성인데 200(VIDEO-001, GUIDE-005), CSRF 표기가 빠진 변경 요청(CAMERA-001·003, VIDEO-006), 429인데 Retry-After 없음(USERS-009·013 ATTEMPTS_EXCEEDED)

## FE에서 할 일

- 회원 화면을 뺀 나머지 화면은 BE 구현에 맞춰 연결한다
- 가이드 영역 형식은 AI 파트 요청(API 명세 v2 도포 정보 대응 확인)대로 S15P31A306-312에서 `shared/guide-area`를 그대로 싣기로 했다(`docs/references/api-spec.md` 로컬 수정 -312)
- 미리보기 레이어 전달 경로, 리포트 상세 필드, 매칭 위치는 해당 API를 구현할 때 BE와 정한다
