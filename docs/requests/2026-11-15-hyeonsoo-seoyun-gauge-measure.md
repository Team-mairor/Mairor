## 요청 배경

앞 요청에서 형식만 맞춰 두자고 했던 게이지 계산을 정했습니다. 계산식은 [shared/gauge 「게이지 값 계산」](../../shared/gauge/README.md#게이지-값-계산-measurev1json), 값과 기대값 시험 데이터는 `shared/gauge/measure.v1.json`, 같은 규칙의 파이썬 구현은 `ai/tools/gauge/measure.py`, 고른 근거는 `docs/experiments/GAUGE_MEASURE.md`에 있습니다.

## 앞 요청에서 바뀌는 것

| 앞 요청 | 바뀐 것 |
| --- | --- |
| 막대 = 「내 화장 효과 크기 ÷ `gauge.effect.size`」 | 그대로 나누면 조명 · 카메라 · 피부톤이 달라 같은 화장이 두 배로 읽혀서, **흰자로 두 화면 색을 맞춘 뒤** 비율을 냅니다(`measure.v1.json`의 `methods`, 시험 데이터 `cases`). 막대 = 비율 × 50(100에서 멈춤), 위치선 50은 그대로입니다 |
| 하위 단계가 여럿이면 값이 있는 첫 하위 단계 | **지금 하위 단계 영역만** 잽니다. 단계 전체(섀도 위 + 아래)로 재면 같은 양이 0.38로 읽혔습니다 |
| `hueShift` · `chromaShift` | 뜻을 정했습니다: 바른 양을 맞춘 뒤 색만 견준 Lab 색상 각도 차이(도, 노란 쪽 +)와 채도 차이(+ 선명 · − 탁함). 「비슷」은 \|색상\| ≤ 2.9도, \|채도\| ≤ 1.6입니다 |
| `gauge` 칸 | `gauge.white`(레퍼런스 흰자 색)가 늘었습니다. 값이 있는 기준에만 있고 없으면 `null`입니다 |

## 요청 내용

- [ ] **계산 붙이기**: `measure.v1.json`의 값으로 아래 순서를 브라우저에서 계산해 주세요. 칸 색 · 조명 빼기는 `baseline.v1.json` 규칙 그대로입니다.
  1. 지금 하위 단계 `guideSets`마다 테두리 안이 칸의 절반 이상인 칸을 영역 칸으로(좌우 짝 부위는 묶음마다 따로)
  2. 0.2초마다 칸 색을 내고 최근 1초를 칸마다 가운데 값으로 모으기
  3. 단계 시작 기준 뒤 조명 변화를 빼고, 영역 칸의 기준 색 · 지금 색을 가운데 값(Lab)으로
  4. 립 · 블러셔 · 섀도 · 쉐딩 · 하이라이트는 흰자 기준 혼합 모델, 눈썹은 자리마다 비율로 맞춰 비율 · 색감 내기
  5. 좌우 중 **비율이 작은 쪽**을 게이지 값으로(한쪽이라도 덜 바르면 「연해요」가 나오도록)
- [ ] **시험 데이터로 맞춰 보기**: `cases`는 3번(영역 색)부터의 입력과 기대값입니다. 같은 입력에서 소수 넷째 자리까지 같은 값이 나오는지 FE 시험으로 확인해 주세요.
- [ ] **게이지를 숨기는 경우**: 아래일 때는 막대를 숨기거나 「잴 수 없어요」로 보여 주세요.

  | 이유 | 뜻 |
  | --- | --- |
  | `noReference` | `gauge`가 없거나 `reason`이 있음(기본 영역 단계 등) |
  | `noWhite` | 색 있는 화장인데 레퍼런스 · 사용자 흰자 중 하나가 없음 |
  | `tooFewCells` | 영역 칸이 6개보다 적음(가림 · 고개 각도) |
  | `thinArea` | 아이라인. 선이 칸보다 얇아 늘 연하게 읽혀 재지 않습니다 |

- [ ] **눈썹은 색감 숨김**: 검정 · 갈색은 색감을 가르지 못해 색감 값이 `null`입니다. 진하기 막대만 보여 주세요.
