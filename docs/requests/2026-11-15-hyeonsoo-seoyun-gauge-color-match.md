## 요청 배경

레퍼런스 영상(링라이트 · 뷰티 필터)과 사용자 캠(방 조명 · 태블릿)은 같은 화장도 다른 색으로 찍힙니다. 맞추지 않으면 조명만 달라도 같은 화장이 레퍼런스보다 두 배 진하게 읽혔습니다. 두 화면 색을 맞추는 방법을 합성 조명 · 피부톤 시험과 시연자 실제 사진(카메라 앱 · 태블릿)으로 견줘 정했습니다. 근거는 `docs/experiments/GAUGE_COLOR_MATCHING.md`, 같은 규칙의 파이썬 구현은 `ai/tools/gauge/color_match.py`의 `method_for`입니다.

- 맨피부만으로 맞추면 「조명이 어두운 것」과 「피부가 어두운 것」을 가를 수 없어, 피부가 어두운 사용자는 같은 양을 발라도 다르게 읽힙니다.
- 흰자는 피부톤과 상관없이 거의 흰색이라 조명 · 카메라 차이만 담습니다. 그래서 색 있는 화장은 **흰자 색**으로 조명을 맞추고 피부톤 차이는 남겨 둡니다.

## 요청 내용

- [ ] **맨얼굴 기준을 잡을 때 흰자 색도 같이 잡기**: 맨얼굴 기준과 같은 정면 · 눈 뜬 사진 15장을 얼굴 지도로 편 뒤, 두 눈 구멍(`leftEye` · `rightEye` 테두리 안) 픽셀 중 밝기 위 25%를 고르고, 채널 하나라도 250 이상(반사광)인 픽셀은 빼고, 남은 픽셀 RGB의 가운데 값을 흰자 색으로 둡니다. 화장한 뒤에는 아이라인 · 속눈썹이 흰자 둘레를 덮어 어둡게 읽혀서(시연자 R 161 → 123) 꼭 맨얼굴일 때 잡아 주세요. 저장 · 전송하지 않는 것은 맨얼굴 기준과 같습니다.
- [ ] **부위별 맞추는 법**: 립 · 블러셔 · 아이섀도 · 쉐딩 · 하이라이트는 흰자 기준 혼합 모델, 눈썹 · 아이라인은 자리마다 비율입니다. 계산식과 기대값 JSON은 브라우저 숫자를 정하는 작업에서 `shared/gauge/`에 채워 보내겠습니다. 지금은 흰자 색을 잡을 자리만 만들어 두시면 됩니다.

## 확인 부탁

## 다음 작업에서 정할 것 (참고)

- 레퍼런스 효과가 아주 작은 단계(시연 영상 눈 뜬 섀도 1.7)는 진하기 비율이 크게 튑니다. 측정 불가로 넘길 기준은 측정 불가 · 값 안정화 작업에서 정합니다.
