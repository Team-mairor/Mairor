# 회원 화면(가입·로그인·로그아웃·기기 관리) FE 구현 요청

- 작성: 김서연
- 받는 사람: FE
- 날짜: 2026-10-29
- 기한: 협의 (BE API는 구현을 마치고 MR 대기 중이라 바로 연동할 수 있습니다)
- 관련 Jira: S15P31A306-206 (BE 로그인·로그아웃), FE 이슈는 S15P31A306-237 로 알고 있습니다. 다르면 알려 주세요
- API 상세: 노션 API 명세와 Swagger(`http://localhost:8080/api/swagger-ui/index.html`, dev 에서만 열림). 이 문서는 **화면을 만들 때 필요한 값**(필드·규칙·시간·오류 처리)을 한곳에 모은 것입니다

## 요청 배경

회원 API(가입·이메일 인증·로그인·로그아웃·내 계정·로그인 기기 관리)가 BE에 구현돼 있는데 FE 화면은 아직 없습니다. 어떤 화면에서 어떤 입력을 받고, 어떤 오류를 어떻게 보여 줘야 하는지, 시간·횟수 제한이 얼마인지 정리했습니다.

**시간·횟수는 BE 설정이라 바뀝니다. 화면에 숫자를 박지 말고, 응답이 주는 초(`expiresInSeconds`, `resendAvailableInSeconds`, `Retry-After`)를 쓰세요.** 아래 숫자는 지금 설정값이고 이해를 돕기 위한 참고입니다.

## 요청 내용

- [ ] 회원가입 화면: 입력 필드, 이메일 중복 확인, 이메일 인증(발송·확인·재발송 타이머), 약관 동의
- [ ] 로그인 화면: 오류별 문구, 잠금 카운트다운
- [ ] 앱 진입 시 로그인 상태 확인, 로그아웃
- [ ] 로그인 기기 관리 화면: 목록, 기기 하나 로그아웃, 전체 로그아웃
- [ ] 공통: 쿠키·CSRF 토큰 처리, 오류 응답 처리

## 1. 공통 규칙

### 호출 방식

- 같은 Origin 의 `/api` 로 호출합니다 (`fetch(..., { credentials: 'same-origin' })`). CORS 설정은 없습니다.
- 세션 쿠키 `__Host-sessionId` 는 HttpOnly 라 JS 로 읽거나 지울 수 없고, 브라우저가 알아서 보냅니다. `https` 이거나 `localhost` 에서만 저장됩니다. 폰에서 PC 로 붙을 때는 `https://<PC IP>:3000` 처럼 https 여야 하고, 그 Origin 이 BE `ALLOWED_ORIGINS` 에 있어야 합니다 (BE 에 알려 주세요).
- 로그인 외 **변경 요청**(POST·PUT·PATCH·DELETE)은 `X-CSRF-TOKEN: <csrfToken>` 헤더가 필요합니다.
  - `csrfToken` 은 **로그인 응답과 `GET /api/v1/users/me` 응답**으로만 받습니다. 메모리에만 두고 localStorage 에는 넣지 않습니다.
  - 로그인할 때마다 새로 발급됩니다. 항상 가장 최근 값을 씁니다. 새로고침하면 `/me` 로 다시 받습니다.
  - 회원가입·이메일 확인·이메일 인증 발송·로그인은 토큰이 필요 없습니다 (대신 허용된 Origin 에서 온 요청만 받습니다).

### 오류 응답 형식

```json
{ "code": "VALIDATION_FAILED", "message": "입력값이 올바르지 않습니다.",
  "details": [ { "field": "password", "reason": "숫자를 1개 이상 포함해야 합니다." } ] }
```

- 화면 분기는 **`code`** 로 합니다. `message` 는 사람이 읽는 문구라 바뀔 수 있습니다.
- `details` 는 입력 필드 오류일 때만 옵니다. `field` 로 해당 입력칸 아래에 `reason` 을 보여 주세요. 한 번에 여러 개가 올 수 있습니다.
- 429 는 `Retry-After` 헤더(초)가 오는 경우가 있습니다. 이 초 동안 버튼을 비활성화하고 카운트다운을 보여 주세요.

| HTTP | code | 의미 |
|---|---|---|
| 400 | `VALIDATION_FAILED` | 입력 오류. `details` 확인 |
| 401 | `UNAUTHORIZED` | 로그인이 필요하거나 세션이 만료됨 |
| 403 | `CSRF_INVALID` | CSRF 토큰이 없거나 틀림. `/me` 로 토큰을 다시 받아 한 번만 재시도 |
| 403 | `FORBIDDEN` | 허용되지 않은 Origin 등. 사용자 문구는 필요 없음 |
| 404 | `NOT_FOUND` | 없는 기기 등 |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | JSON 이 아닌 본문 (`Content-Type: application/json` 확인) |
| 429 | `TOO_MANY_REQUESTS` | 서버 혼잡 또는 요청 한도. `Retry-After` 이후 재시도 |
| 500 | `INTERNAL_ERROR` | 서버 오류. "잠시 후 다시 시도" |
| 503 | `SERVICE_UNAVAILABLE` | 서버가 일시적으로 요청을 처리하지 못함(DB 장애 등). **로그아웃된 것이 아닙니다.** 로그인 상태를 지우지 말고 "잠시 후 다시 시도해 주세요" 안내 후 재시도. 로그인·로그아웃이 503 이면 완료되지 않은 것입니다 |

## 2. 회원가입 화면

호출 순서:

```
이메일 입력 ─▶ 중복 확인 ─▶ (이메일 인증을 요구할 때) 인증번호 발송 ─▶ 인증번호 입력·확인 ─▶ 가입
```

가입 API 는 **로그인하지 않습니다.** 가입 성공 후 로그인 화면으로 보내거나, 같은 이메일·비밀번호로 `POST /api/v1/users/login` 을 이어서 호출하세요. 어느 쪽으로 할지는 FE·기획에서 정해 주세요.

### 2-1. 입력 필드 (`POST /api/v1/users/signup`)

| 필드 | 화면 항목 | 필수 | 규칙 (서버 검증과 같게 FE 에서도 즉시 검증하세요) | 서버 오류 `details.field` |
|---|---|---|---|---|
| `email` | 이메일 | 필수 | 최대 254자, `a@b.c` 형태. 서버가 앞뒤 공백 제거·소문자 변환 | `email` |
| `password` | 비밀번호 | 필수 | 8~64자, 영문자·숫자·특수문자 각 1개 이상 (아래 주의 참고) | `password` |
| `passwordConfirm` | 비밀번호 확인 | 필수 | `password` 와 같은 값 | `passwordConfirm` |
| `nickname` | 닉네임 | 선택 | 2~20자, 한글·영문·숫자·밑줄(`_`) | `nickname` |
| `name` | 이름 | 선택 | 2~50자, 한글·영문·공백 | `name` |
| `phone` | 휴대폰 번호 | 선택 | `010` 등 `01[016789]` 로 시작하는 숫자 10~11자리. 하이픈·공백은 서버가 제거하므로 입력은 허용해도 됨. 국가번호(+82) 불가 | `phone` |
| `birthDate` | 생년월일 | 선택 | `YYYY-MM-DD`. 오늘보다 과거, 1900-01-01 이후, **만 14세 이상**(한국 시간 기준) | `birthDate` |
| `gender` | 성별 | 선택 | `MALE` 또는 `FEMALE` (그 외 값 불가) | `gender` |
| `agreements` | 약관 동의 | 필수 | 아래 2-2 | `agreements.TERMS` 등 |
| `emailVerificationToken` | (화면에 안 보임) | 인증 요구 시 필수 | 인증번호 확인 응답의 `verificationToken` | — |

- 선택 필드는 입력하지 않으면 **키를 빼거나** 문자열 필드는 빈 문자열로 보내도 됩니다 (빈 문자열은 없는 값으로 처리). 단 `birthDate` 는 빈 문자열을 보내면 400 이니 값이 없으면 키를 빼 주세요.
- **비밀번호 주의점**
  - 특수문자는 **ASCII 기호**(`!@#$%^&*` 등)만 인정합니다. 공백·한글·이모지는 특수문자로 세지 않습니다.
  - 길이 상한이 64자 외에 **UTF-8 72바이트**가 있습니다. 영문·숫자·기호는 1바이트지만 한글은 글자당 3바이트라서, 한글을 섞으면 64자보다 훨씬 짧은 길이에서 막힙니다. 한글 비밀번호는 권장하지 않는다는 안내가 있으면 좋습니다.
  - 규칙을 어긴 항목마다 `details` 가 따로 옵니다 (예: "영문자를 1개 이상 포함해야 합니다.", "숫자를 1개 이상 포함해야 합니다.", "특수문자(!@#$ 등 ASCII 기호)를 1개 이상 포함해야 합니다."). 체크리스트처럼 보여 주기 좋습니다.
  - 비밀번호는 앞뒤 공백을 자르지 않고 그대로 보냅니다. 보기/숨기기 토글은 FE 재량입니다.
- 응답 `201`:
  ```json
  { "userId": "…", "email": "user@example.com", "nickname": null, "provider": "LOCAL", "createdAt": "2026-10-29T01:02:03Z" }
  ```
  이름·휴대폰·생년월일·성별은 저장만 하고 응답에 내려주지 않습니다. `nickname` 을 입력하지 않았으면 `null` 입니다.

### 2-2. 약관 동의

`agreements` 는 아래 4개를 배열로 보냅니다. `version` 은 **서버의 현재 버전과 같아야** 합니다 (현재 모두 `2026-10-26`). 버전이 바뀌면 BE 가 알려 드립니다.

| `type` | 화면 문구(안) | 필수 | 비고 |
|---|---|---|---|
| `TERMS` | 서비스 이용약관 동의 | 필수 | `agreed: true` 여야 가입됨 |
| `PRIVACY` | 개인정보 수집·이용 동의 | 필수 | 〃 |
| `AGE_OVER_14` | 만 14세 이상입니다 | 필수 | 〃 |
| `MARKETING` | 마케팅 정보 수신 동의 | 선택 | `agreed: false` 로 보내도 됨. 버전 검사 없음 |

```json
"agreements": [
  { "type": "TERMS", "version": "2026-10-26", "agreed": true },
  { "type": "PRIVACY", "version": "2026-10-26", "agreed": true },
  { "type": "AGE_OVER_14", "version": "2026-10-26", "agreed": true },
  { "type": "MARKETING", "version": "2026-10-26", "agreed": false }
]
```

- 같은 `type` 을 두 번 보낼 수 없습니다.
- 필수 약관 중 하나라도 빠지거나 `false` 거나 버전이 다르면 `400 USERS_REQUIRED_AGREEMENT_MISSING` 이고, `details[].field` 가 `agreements.TERMS` 처럼 약관별로 옵니다 (`reason`: "필수 약관에 동의해야 합니다." / "약관 버전이 최신이 아닙니다." 등). 필수 약관 3개가 모두 체크되기 전에는 가입 버튼을 비활성화해 주세요.
- 약관 본문 링크·내용은 FE/기획에서 정해 주세요 (BE 는 버전 문자열만 검증).

### 2-3. 가입 오류

| HTTP | code | 처리 |
|---|---|---|
| 400 | `VALIDATION_FAILED` | `details` 의 `field` 별로 입력칸 아래에 표시 |
| 400 | `USERS_REQUIRED_AGREEMENT_MISSING` | 약관 영역에 표시 |
| 400 | `USERS_EMAIL_NOT_VERIFIED` | 이메일 인증을 요구하는 환경에서 토큰이 없거나 만료·불일치. 인증 단계로 되돌림 |
| 409 | `USERS_EMAIL_DUPLICATE` | "이미 가입된 이메일입니다" (중복 확인 이후에도 동시에 가입되면 여기서 걸림) |
| 403 | `FORBIDDEN` | 허용되지 않은 Origin (개발 중이면 BE 에 알려 주세요) |

### 2-4. 이메일 중복 확인 (`POST /api/v1/users/email-availability`)

- 요청: `{ "email": "user@example.com" }` (이메일은 URL 이 아니라 본문으로 보냅니다)
- 응답 `200`: `{ "email": "user@example.com", "available": true }` — `email` 은 서버가 정규화한 값입니다.
- 호출 시점은 FE 에서 정해 주세요 (입력칸을 벗어날 때 또는 "중복 확인" 버튼). 타이핑마다 호출하지 마세요.
- **한도**: 같은 IP 에서 1분에 30번 (초과 시 `429 USERS_EMAIL_CHECK_RATE_LIMITED` + `Retry-After`).
- 결과는 예약이 아닙니다. `available: true` 여도 가입 시점에 다시 검사하므로 409 가 날 수 있습니다.
- 이메일을 수정하면 이전 확인 결과를 무효로 돌리고 다시 확인하게 해 주세요.

### 2-5. 이메일 인증 (가입에 이메일 인증을 요구할 때)

가입에 인증을 요구할지는 BE 설정(`SIGNUP_REQUIRE_EMAIL_VERIFICATION`)입니다. **지금 기본값은 꺼짐이고 정책이 확정되면 켭니다.** 꺼져 있으면 `emailVerificationToken` 없이도 가입되고, 토큰을 보내도 무시됩니다. 따라서 화면은 인증 단계를 포함해 만들어 두고, 켜짐/꺼짐 전환은 설정만 바꾸면 되도록 해 주세요 (현재 FE 가 켜짐 여부를 알아내는 API 는 없습니다. 필요하면 BE 에 요청해 주세요).

**① 인증번호 발송** `POST /api/v1/users/email-verification` — 요청 `{ "email": "…" }`

- 응답 `202`: `{ "expiresInSeconds": 600, "resendAvailableInSeconds": 60 }`
  - `expiresInSeconds`: 인증번호 입력 제한 시간. 입력창 옆에 `09:59` 같은 카운트다운을 보여 주세요. 0 이 되면 입력을 막고 "다시 받기"를 안내합니다.
  - `resendAvailableInSeconds`: 재발송 버튼이 다시 활성화되기까지의 시간.
- 인증번호는 **숫자 6자리**입니다. 다시 받으면 **이전 번호는 무효**가 되고 틀린 횟수도 초기화됩니다.
- 이미 가입된 이메일에는 보내지 않고 `409 USERS_EMAIL_DUPLICATE` 를 줍니다.

**② 인증번호 확인** `POST /api/v1/users/email-verification/verification` — 요청 `{ "email": "…", "code": "123456" }`

- 응답 `200`: `{ "verificationToken": "…", "expiresAt": "2026-10-29T01:32:03Z" }`
  - `verificationToken` 을 가입 요청의 `emailVerificationToken` 에 넣습니다. **이 응답에서만** 받을 수 있으니 보관해 두세요.
  - 토큰은 **그 이메일에만** 유효하고 `expiresAt`(발급 후 30분)까지입니다. 가입 직전에 이메일 입력값을 바꾸면 다시 인증해야 합니다. 시간이 지나 `USERS_EMAIL_NOT_VERIFIED` 가 오면 인증 단계로 되돌려 주세요.
- 인증에 성공하면 이메일 입력칸을 잠그고 "인증 완료" 표시를 해 주세요.

**인증 관련 시간·횟수 (현재 설정)**

| 항목 | 값 | FE 처리 |
|---|---|---|
| 인증번호 유효 시간 | 10분 | 발송 응답 `expiresInSeconds` 로 카운트다운 |
| 재발송 간격 | 60초 | 발송 응답 `resendAvailableInSeconds` 로 버튼 비활성화 |
| 같은 이메일로 발송 가능 횟수 | 1시간에 5번 | 초과 시 429 + `Retry-After` |
| 같은 IP 에서 발송 가능 횟수 | 10분에 10번 | 초과 시 429 + `Retry-After` |
| 인증번호 틀릴 수 있는 횟수 | 5번 | 초과 시 `429 USERS_EMAIL_CODE_ATTEMPTS_EXCEEDED`. 번호를 다시 받아야 함 |
| 인증 토큰 유효 시간 | 30분 | `expiresAt` |

**인증 오류**

| HTTP | code | 처리 |
|---|---|---|
| 400 | `USERS_EMAIL_CODE_INVALID` | "인증번호가 일치하지 않아요" (입력칸 유지, 재입력) |
| 410 | `USERS_EMAIL_CODE_EXPIRED` | "인증번호가 만료됐거나 요청 기록이 없어요" → 다시 받기 안내 |
| 429 | `USERS_EMAIL_CODE_ATTEMPTS_EXCEEDED` | "너무 많이 틀렸어요" → 인증번호 다시 받기 안내 (`Retry-After` 없음) |
| 429 | `USERS_EMAIL_SEND_RATE_LIMITED` | 발송 한도(쿨다운·시간당·IP). `Retry-After` 만큼 대기 |
| 409 | `USERS_EMAIL_DUPLICATE` | 이미 가입된 이메일 |
| 503 | `USERS_EMAIL_SEND_FAILED` | "메일을 보내지 못했어요. 잠시 후 다시 시도해 주세요" (이 경우 재발송 간격은 소모되지 않음) |
| 400 | `VALIDATION_FAILED` | 이메일 형식 오류, 인증번호가 6자리 숫자가 아님 |

개발 중에는 BE 가 `MAIL_ENABLED=false` 면 메일을 보내지 않고 **서버 로그에만** 인증번호를 남깁니다. 실제 메일이 필요하면 BE 에 알려 주세요.

## 3. 로그인 화면 (`POST /api/v1/users/login`)

- 요청: `{ "email": "…", "password": "…" }` — 이메일은 서버가 공백 제거·소문자 변환하므로 가입 때와 같게 처리됩니다. 비밀번호 강도 규칙은 로그인에서 검사하지 않습니다. 이메일은 최대 254자, 비밀번호는 최대 256자입니다.
- 응답 `200`: `{ "user": { userId, email, nickname, provider, createdAt }, "csrfToken": "…" }` — `csrfToken` 을 메모리에 보관하고 홈으로 이동합니다.
- 처리 중에는 버튼을 막아 중복 요청을 방지해 주세요.

| 응답 | 화면 처리 |
|---|---|
| 401 `USERS_INVALID_CREDENTIALS` | "이메일 또는 비밀번호를 확인해 주세요" — **어느 쪽이 틀렸는지 표시하지 마세요.** 가입되지 않은 이메일, 틀린 비밀번호, Google 전용 계정이 모두 같은 응답입니다 |
| 429 `USERS_LOGIN_RATE_LIMITED` | 같은 이메일로 여러 번 실패해서 잠김. `Retry-After`(초) 동안 버튼 비활성화 + 카운트다운. 잠겨 있는 동안은 비밀번호가 맞아도 429. **실패 횟수 숫자를 화면에 쓰지 마세요** |
| 429 `TOO_MANY_REQUESTS` | 서버가 일시적으로 혼잡. "잠시 후 다시 시도해 주세요", `Retry-After`(보통 1초) 후 재시도 |
| 400 `VALIDATION_FAILED` | 이메일·비밀번호가 비었거나 길이 초과 |
| 403 `FORBIDDEN` | 허용되지 않은 Origin |

(현재 설정: 3번 실패하면 30초 잠금. 5번으로 올릴 예정입니다. 숫자는 바뀌므로 화면에 쓰지 않습니다.)

## 4. 앱 진입·로그아웃·기기 관리

### 앱 진입 `GET /api/v1/users/me`

- 앱을 열 때마다 호출합니다. 응답은 로그인 응답과 같은 모양 `{ user, csrfToken }` 입니다.
- `200`: 홈으로 이동하고 `csrfToken` 을 갱신합니다. **이 호출이 로그인 유지 기간을 연장합니다.** 별도의 주기적 호출(keep-alive)은 필요 없습니다.
- `401`: 로그인 화면으로. 이 기기에 로그인 이력이 있었다면 "로그인이 만료됐어요" 안내를 보여 줍니다.
- 로그인 유지 기간 (현재 설정, 화면에 숫자 쓰지 않기): 마지막 요청으로부터 **3일** 동안 요청이 없으면 만료, 계속 써도 로그인한 지 **30일**이 지나면 만료됩니다.

### 로그아웃 `POST /api/v1/users/logout` (`X-CSRF-TOKEN` 필요)

| 응답 | 처리 |
|---|---|
| `204` | 로컬 상태(csrfToken, 이력 플래그, 카메라·메모리 개인 데이터)를 지우고 로그인 화면으로. 다른 기기의 로그인은 유지됩니다 |
| `401` | 이미 로그아웃된 상태. 위와 같이 정리 |
| `403 CSRF_INVALID` | `GET /me` 로 확인: `200` 이면 받은 새 `csrfToken` 으로 **한 번만** 재시도, `401` 이면 로그아웃된 상태로 정리 |
| 네트워크 오류·5xx | "로그아웃 완료 여부를 확인하지 못했어요" + 재시도. 완료로 표시하지 마세요 (HttpOnly 쿠키는 FE 가 지울 수 없습니다) |

진행 중인 가이드가 있으면 종료 확인을 거친 뒤 호출해 주세요.

### 로그인 기기 관리 (모두 로그인 필요, 변경 요청은 `X-CSRF-TOKEN` 필요)

| API | 용도 | 응답 |
|---|---|---|
| `GET /api/v1/users/me/sessions` | 내 기기 목록 | `200 { items: [ { sessionRef, device, createdAt, lastAccessedAt, current } ] }` |
| `DELETE /api/v1/users/me/sessions/{sessionRef}` | 기기 하나 로그아웃 | `204` (없거나 남의 값이면 `404`) |
| `DELETE /api/v1/users/me/sessions` | 전체 기기 로그아웃 (현재 기기 포함) | `204` |

- 목록은 **최근에 쓴 기기가 먼저** 옵니다. `current: true` 인 항목이 지금 쓰는 기기이니 "이 기기" 로 표시해 주세요.
- `device` 는 "Chrome · Windows" 같은 요약 문자열입니다. IP 는 주지 않습니다. 알 수 없으면 "알 수 없는 기기" 로 옵니다.
- `sessionRef` 는 목록에서 기기를 고르는 용도의 값입니다 (쿠키의 세션 ID 와 다른 값).
- **현재 기기**를 지정해 지우면 로그아웃과 같습니다. 성공 후 로컬 상태를 지우고 로그인 화면으로 보내 주세요. 다른 기기를 지운 경우에는 현재 화면을 유지하고 목록만 새로 받으면 됩니다.
- 전체 로그아웃은 성공 후 로컬 상태를 지우고 로그인 화면으로 보냅니다. 요청 시점에 있던 세션만 끊으므로, 같은 순간 다른 기기에서 막 시작된 로그인까지 막지는 못합니다.
- 전체 로그아웃이 `500` 이면 일부 기기만 끊겼을 수 있고 **현재 기기는 로그인이 유지된 상태**입니다. 로컬 상태를 지우지 말고 "일부 기기를 로그아웃하지 못했어요" 안내와 함께 같은 요청을 다시 보낼 수 있게 해 주세요.
- 목록 응답은 캐시되지 않습니다 (`Cache-Control: no-store`). 화면에 들어갈 때마다 새로 요청해 주세요.

## 5. 개발·테스트 팁

- Swagger 에서 `login` 을 실행하면 쿠키와 `csrfToken` 이 자동으로 처리돼 이후 API 를 바로 호출해 볼 수 있습니다.
- 테스트 계정이 필요하면 Swagger 의 `회원가입` 으로 만들 수 있습니다 (이메일 인증을 요구하지 않는 설정일 때).
- FE 개발 서버(`http://localhost:3000`, `https://localhost:3000`)는 BE dev 기본 `ALLOWED_ORIGINS` 에 들어 있습니다. 다른 주소를 쓰면 알려 주세요.
