## 요청 배경

AI는 S15P31A306-417에서 운영 가이드 작업 기록으로 결과 형식, BE 저장, 9개 부위 상태, 구간별 시간을 확인했습니다([GUIDE_JOB_OPS_TIMING.md](../experiments/GUIDE_JOB_OPS_TIMING.md)). 확인한 11-04 · 11-06 두 실행은 모두 S15P31A306-333(가이드 영역 생성 시간과 메모리 줄이기) 병합 전 코드입니다. 333은 11-09 19:27 master에 병합돼 운영에 배포됐고(BE 서버 이미지 `cf2becd6`), 그 뒤 운영에서 돈 가이드 작업 기록은 아직 없습니다.

지금 운영 코드로 한 번 돈 기록이 있어야, 콜백 대기 시간(`AI_CALLBACK_TIMEOUT`)과 진행률 비중(`progressPercent` · `estimatedRemainingSeconds`)을 서버 흉내 어림이 아니라 운영 값으로 드릴 수 있습니다.

- [ ] 그 실행 동안 다른 분석 요청이 겹치지 않게 해 주세요. AI 영역 작업은 한 번에 하나만 돌아서(`AREA_MAX_CONCURRENCY=1`) 겹치면 기다린 시간이 측정에 섞입니다
- [ ] 끝나면 실행 시각과 AI 작업 ID(`analysis_jobs.ai_job_id`)를 이 문서를 올린 MR 댓글로 알려 주세요. 기록은 Phoenix에서, guideId는 운영 DB에서 AI가 직접 찾습니다
- [ ] 사진을 어느 길로 뽑았는지도 알려 주세요(운영자가 올린 영상 → BE worker / YouTube → 노트북 처리기). 노트북 처리기는 지금 사진 규칙이 BE worker와 달라([노트북 사진 규칙 요청](2026-11-09-hyeonsoo-hyeongjun-processor-frame-rule.md)) 결과와 시간을 지난 두 실행과 견줄 수 없습니다. 그 규칙이 맞춰지기 전이면 BE worker 길로 부탁드립니다
