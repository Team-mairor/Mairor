# 가이드 영역 검증 지표와 합격선

2026-11-03 · S15P31A306-286

사람이 칠한 정답 그림 없이, 시험 영상 하나에서 뽑은 데이터만으로 가이드 영역(립·블러셔·눈썹·섀도·아이라인)이 맞는지 재는 지표와 합격선을 정했다. 지금 코드의 성적과 문제마다의 원인도 함께 남긴다. 영역을 고친 뒤에는 같은 도구로 다시 재서 이 문서의 「지금 코드 성적」과 견준다.

## 요약

- 지표 다섯 가지: 잡음, 안정성, 경계, 색 변화, 넓음
- 합격선은 모든 지표가 정상인 **기준 사례(눈썹 s8, 립 s27)가 조금 여유 있게 통과하는 값**이다
- 지금 코드: 실제 바른 단계·쪽 24개 중 **합격 5, 불합격 13, 못 찾음 6**. 잡음은 눈썹만 합격이라 다섯 부위 모두 불합격
- 지표는 쪽마다 찾은 영역을 잰다. 화면에는 서비스가 좌우를 맞춘 영역이 나간다
- 문제의 원인은 대부분 **영역 데이터**다. 얼굴 주소 변환과 FE 그리기는 시험 영상 얼굴에서 정확했다

## 지표

| 지표 | 무엇을 잡나 | 어떻게 재나 | 도구 |
| --- | --- | --- | --- |
| 잡음 | 안 발랐는데 발랐다고 함 | 그 부위를 건드리지 않은 단계에서 사진 쌍을 만들어 부위 코드와 같은 계산을 한다. 영역이 나오면 헛것이다. 간격 1·10·30·60·120초, 4초마다. 섀도·아이라인은 눈썹을 그리는 단계도 뺀다 | `tools/noise_metric.py` |
| 안정성 | 사진 몇 장에 따라 결과가 흔들림 | 직전·직후 사진 창을 0·1·2초씩 옮긴 9조합(립 3조합)으로 다시 찾는다. 겹침을 "몇 칸 흔들린 것과 같은지"로 바꿔 부위 세로로 나눈다 | `tools/stability_metric.py` |
| 경계 | 입술·눈썹 밖으로 넘침, 눈 침범 | 얼굴 분할 모델(BiSeNet)이 칠한 부위와 견준다. 블러셔는 볼 경계가 모델에 없어 재지 않는다 | `tools/boundary_metric.py` |
| 색 변화 | 바른 곳을 놓침, 엉뚱한 순간을 잡음 | 단계 앞뒤 10초를 2초마다 찍어 영역 안과 바깥 띠의 색 변화를 시간 순서로 본다. 바깥 띠는 부위 코드의 흐림이 번지는 거리(흐림 폭 × 2) 밖에 둔다 | `tools/timing_metric.py` |
| 넓음 | 바른 곳보다 넓게 잡음 | 영역 칸 중 영역 안 상위 10% 값의 절반 이상으로 바뀐 칸의 비율(진한 칸 비율) | `tools/timing_metric.py` |

색 값은 모든 지표에서 부위 코드와 같은 값을 쓴다(눈썹 어두워진 양, 섀도·블러셔 붉어진 양, 아이라인 바뀐 칸, 립 붉은 기).

모든 지표는 부위 코드가 **쪽마다 찾은 영역**(`find_*_area`, 잡음은 `check_*_area`)을 잰다. 서비스(`guide_area_builder.py`)는 그 뒤에 좌우를 맞춘다. 눈썹·섀도·블러셔는 두 쪽 중 하나를 골라 좌우로 뒤집어 양쪽에 쓴다. 아이라인은 앞 아이라인 단계에서 안내한 칸을 뺀 뒤, 윗선·아랫선마다 한 눈을 골라 뒤집어 쓴다. 그래서 지표는 화면에 나가는 영역이 아니라, 쪽마다 얼마나 잘 찾는지를 본다.

### 섀도·아이라인 잡음에서 눈썹 단계를 뺀 근거

섀도를 찾는 범위는 눈썹 테두리 바로 아래까지이고, 찾은 변화를 흐려 번지게 한다. 그래서 눈썹을 그리는 단계(s8)를 안 건드린 단계로 쓰면 눈썹이 진해진 변화가 헛것으로 셀 수 있다. 서비스는 눈 화장 단계의 직전·직후 사진 사이에 눈썹을 그리는 일이 드물어, 이 단계를 잡음에서 뺐다. 아이라인도 같은 단계에서 오른쪽만 튀어 함께 뺐다. 아이라인 범위는 눈썹에서 멀어서 원인(손 위치, 눈썹을 치켜올림 등)은 사진으로 확인하지 않았다.

s8을 넣고 잰 결과를 쌍이 시작한 단계로 나누면 다음과 같다.

| 부위·쪽 | s8 눈썹 | s9 컨투어 | s22 블러셔 | s26 립 | s27 립 |
| --- | --- | --- | --- | --- | --- |
| 섀도 왼쪽 | 26% | 22% | 33% | 27% | 30% |
| 섀도 오른쪽 | **62%** | 40% | 38% | 7% | 20% |
| 아이라인 왼쪽 | 13% | 14% | 0% | 19% | 22% |
| 아이라인 오른쪽 | **47%** | 11% | 17% | 11% | 33% (9쌍) |

헛것 비율은 섀도 26.7% · 40.3% → 27.1% · 27.0%, 아이라인 12.7% · 25.1% → 13.7% · 10.1%로 바뀌었고, 판정은 그대로다. s8을 빼도 섀도 오른쪽은 컨투어·블러셔 단계에서 높고, 섀도 왼쪽은 눈에서 먼 립 단계에서도 27~30%다. 섀도 헛것은 눈썹 단계 탓만이 아니다.

### 경계 모델을 고른 근거

44장에서 두 모델을 견줬다.

| | BiSeNet ResNet18 | SegFormer-B5 |
| --- | --- | --- |
| 두 모델 일치 (입술·눈썹·눈) | 0.871 · 0.83 · 0.78 | |
| 속도 (장당) | **0.19초** | 1.24초 |
| 사용 조건 | 코드는 MIT, 가중치는 CelebAMask-HQ로 학습해 그 조건(비상업 연구)을 따른다 | 비상업 연구·교육 (CelebAMask-HQ로 학습) |

일치가 높아 하나만 써도 되고, 빠른 BiSeNet을 골랐다. 모델 파일은 저장소에 두지 않는다. 도구의 `MODEL_URL`에서 받아 경로를 넘기면 `MODEL_SHA256`과 같은지 먼저 확인한다. 두 모델 모두 개발용 측정에만 쓰고 서비스 코드에는 넣지 않는다.

### 흔들림을 크기 대비로 바꾼 근거

## 화면 점검

### 확인한 방법

| 방법 | 보는 것 |
| --- | --- |
| 영역을 영상 사진 위에 다시 그리기 (`tools/draw_guide_area.py`) | 얼굴 주소를 그 사진의 얼굴 점으로 다시 계산해도 제자리에 오는지 |
| 화장 전 얼굴에 가이드를 대고 화장 후와 견주기 | 영상 속 사람이 실제로 바른 곳을 가이드가 덮는지. 얼굴이 같아 얼굴 차이가 없다 |
| FE 튜토리얼 화면에 카메라 대신 영상 사진 넣기 | FE가 같은 영역을 같은 자리에 그리는지 |
| FE 튜토리얼 화면을 실제 카메라로 보기 | 가이드가 뜨는지, 사용자 얼굴에서 어떻게 보이는지 |

화면 점검은 지표와 달리 서비스가 실제로 내보낸 영역(`guide_area.json`)으로 했다.

## 한계

- 정답 그림이 없어서 지표는 "틀린 흔적"을 찾는다. 다 통과해도 "몇 % 맞다"고는 말할 수 없다
- 지표는 쪽마다 찾은 영역을 잰다. 좌우를 맞춘 뒤 화면에 나가는 영역은 재지 않았다
- 색 변화 도구는 조심할 구간을 건너뛰지 않는다. 섀도 s11·s17·s19, 아이라인 s12, 립 s27에서 앞뒤 시점 일부가 그 구간에 든다. 그 시점을 빼고 다시 계산해도 판정은 같다. 립 s27은 끝 뒤 시점이 모두 아웃트로라 빼면 유지 비를 낼 수 없다
- 기준 사례가 세 개(눈썹 s8 양쪽, 립 s27)뿐이다
- 영상 하나로 정했다. 다른 영상의 정확도는 재지 않았다
- 눈 침범 합격선은 잠정이다
- 넓음 지표는 영역 안의 상대 비교라, 영역 전체가 고르게 옅으면 넓어도 통과할 수 있다

| 순서 | 명령 | 걸린 시간 |
| --- | --- | --- |
| 1 | `uv run python tools/noise_metric.py samples/local_03_seq` | 약 30분 |

| 3 | `uv run python tools/boundary_metric.py samples/local_03_seq <모델 파일>` | 약 5분 |

결과는 `samples/local_03_seq/output/`의 `noise.json`·`stability.json`·`boundary.json`·`timing.json`·`scorecard.json`이다(git 제외). 경계 도구는 `onnxruntime`(dev 의존성)이 필요하다.
