# 바른 곳 찾기 모델 학습과 설정 탐색

단계 직전·직후 얼굴 지도 두 장을 받아 칸마다 바른 자리를 칠하는 모델을 학습하고, 출발 모델과 학습 설정을 검증 점수로 고른 기록이다 (S15P31A306-428). 정답지는 [바른 곳 찾기 모델 학습 정답지](GUIDE_AREA_TRAIN_LABELS.md), 스크립트와 실행 순서는 [ai/tools/guide_area_training/README.md](../../ai/tools/guide_area_training/README.md)에 있다. 규칙과 모델 가운데 무엇을 쓸지는 여기서 정하지 않는다. 시험 영상으로 견주는 비교 시험에서 정한다.


## 요약

- 고른 설정: 얼굴 분할 모델 BiSeNet에서 이어 학습, 학습률 1e-3(학습률을 끝까지 같게), 바른 칸 손실 가중치 1, 실제 장면 정답지 안 섞음(합성만), 지도 1024, 묶음 4건.
- 최종 가중치는 이 설정을 시작값 428로 15에폭 학습한 실행의 14에폭이다. 검증 평균(자리 7개 IoU) 0.874, 같은 설정 두 시작값 평균 0.868. 립 0.91·블러셔 0.88·눈썹 0.99·섀도 윗눈두덩 0.99·섀도 눈 밑 0.65·아이라인 윗라인 0.79·아랫라인 0.85, 아무것도 안 바른 쌍에 칠한 칸 0.1%.
- 사람이 고르지 않았다. 축마다 후보를 시작값 두 개로 학습해 검증 점수 평균이 높은 값을 도구(`search.py`)가 골랐다. 같은 설정도 시작값에 따라 점수가 크게 흔들려서다.
- 검증은 학습과 다른 채널 영상 2개의 합성 정답지 334건이 사실상 전부다. 실제 화장 장면 검증은 립 2건뿐이라, 실제 화장을 얼마나 맞히는지는 시험 영상 비교에서 따로 재야 한다.
- 427 첫 정답지로 한 첫 탐색은 검증이 학습과 겹친 것이 드러나 고르기에 쓰지 않았다. 427이 고친 정답지로 처음부터 다시 했다.
- 교육용 서버 GPU 5번(H200)에서 돌렸다. 정답지를 처음에 메모리에 올리고 소수 변환을 GPU로 옮겨, 같은 학습이 노트북보다 약 4배 빨라졌다.

## 입력과 출력

| 항목 | 내용 |
| --- | --- |
| 입력 | 직전 얼굴 지도(`before.png`)와 직후 얼굴 지도(`after.png`)를 겹친 6겹. 지도는 1024 × 1024 RGB이고, 설정에 따라 512로 줄여 넣는다 |
| 출력 | 칸마다 자리 번호 하나. 0 안 바름, 1 `lip`, 2 `blush`, 3 `brow`, 4 `eyeshadowUpper`, 5 `eyeshadowUnder`, 6 `eyelinerUpper`, 7 `eyelinerUnder` |
| 정답 | `label.png`. 모름 칸(255: 얼굴 밖, 가려진 칸, 흐린 가장자리 등)은 손실과 점수에서 뺀다 |
| 밝기·좌우 | 학습 때 절반은 좌우를 뒤집고, 전후에 같은 밝기 배수(0.85~1.15)를 곱한다. 얼굴 지도는 좌우가 대칭이고 자리 번호에 왼쪽·오른쪽이 없어 뒤집어도 번호는 그대로다 |

## 출발 모델 두 후보

| 후보 | 구조 | 매개변수 | 출발점 |
| --- | --- | --- | --- |
| `bisenet` | 얼굴 분할 모델 BiSeNet(ResNet18). 첫 층을 3겹에서 6겹으로 늘리고(원래 가중치를 전·후에 반씩), 세 출력 머리를 8칸으로 새로 만든다 | 13,818,600 | [yakhyo/face-parsing](https://github.com/yakhyo/face-parsing) `resnet18.pt` (가림 찾기 모델과 같은 원본) |
| `small` | 작은 U-Net. 16·32·64·128 너비로 세 번 줄였다가 같은 크기 층을 이어 붙이며 올라온다. GroupNorm | 488,552 | 처음부터 |

BiSeNet은 앞부분(ResNet18)을 학습률의 10분의 1로 천천히 고치고, BatchNorm 통계는 원본 그대로 둔다. 묶음이 4건뿐이라 통계가 흔들려서다. 전후가 같은 그림이면 늘린 첫 층이 원래 모델과 같은 값을 낸다(`test_widened_first_layer_answers_like_the_original_when_before_equals_after`).

## 손실과 점수

| 항목 | 내용 |
| --- | --- |
| 손실 | 가중 교차 엔트로피. 안 바름은 1, 바른 자리는 모두 「바른 칸 손실 가중치」. 모름 칸은 뺀다. BiSeNet은 두 보조 출력의 손실을 0.4배 더한다 |
| 검증 점수 | 자리 7개의 IoU 평균(`meanIoU`). IoU = 맞게 칠한 칸 ÷ (예측이나 정답이 칠한 칸), 모름 칸은 세지 않는다. 검증에 한 번도 안 나오고 예측도 안 한 자리는 평균에서 뺀다 |
| 같이 적는 값 | 자리별 IoU, 아무것도 안 바른 정답지에서 바름으로 칠한 칸 비율(`cleanFalsePositive`), 실제 장면만의 점수 |
| 가장 좋은 에폭 | 실행마다 검증 점수가 가장 높은 에폭의 가중치를 `best.pt`로 남긴다 |

## 시운전

427 정답지가 만들어지는 동안, 코드가 끝까지 도는지와 시간·메모리를 보려고 짧게 돌렸다. 그때 다 쓰인 정답지가 시험 나눔뿐이어서 그중 54건(립 17·블러셔 18·눈썹 17·섀도 2, 안 바른 쌍 7)을 사본으로 떼어 썼다. 코드 확인과 시간 재기에만 썼고, 가중치는 지웠으며, 모델·설정 고르기에는 쓰지 않았다.

### 시운전에서 찾은 것

- 모델은 얼굴 밖 칸(지도의 약 35%)을 아무 번호로나 칠한다. 얼굴 밖은 모름 칸이라 배운 적이 없어서다. 점수에는 안 들어가지만, 모델 결과를 쓰는 곳에서는 얼굴 안 칸만 남겨야 한다. `plot.py`의 예측 그림도 모름 칸을 지우고 그린다.
- `small`이 립을 덜 배운 것은 데이터 문제가 아니었다. 립 정답지 그림에서 정답 테두리가 칠한 입술과 맞았고, 같은 정답지로 `bisenet`은 0.97까지 맞혔다.

## 돌린 곳과 속도

처음에는 노트북 GPU로 탐색을 시작했다가, 교육용 서버(JupyterLab `jupyter12`, NVIDIA H200 NVL) GPU 5번으로 옮겨 처음부터 다시 돌렸다. 서버는 여러 팀이 같이 써서 `CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=5`로 5번 한 장만 보이게 하고, CPU 계산 스레드를 1로 묶고, 사진 읽는 일꾼은 12개만 썼다. 프로그램은 서버의 conda 가상환경 `a306_428`(Python 3.12, torch 2.11.0 CUDA 12.8용)에만 깔았다.

서버로 옮겨도 처음에는 노트북과 속도가 비슷했다. GPU가 아니라 정답지를 읽어 넘기는 쪽이 막고 있었다. 정답지 한 건을 읽는 데 302ms가 들었고, 그중 159ms가 CPU에서 지도를 소수로 바꾸고 밝기를 곱하는 계산이었다. 소수로 바꾸면 한 건이 6MB에서 24MB로 커져 GPU로 넘기는 양도 네 배가 된다. 그래서 일꾼은 0~255 정수 그대로 넘기고, 밝기 곱하기와 정규화는 GPU에서 하도록 바꿨다(`train.to_input`). 계산식은 같고, 옛 CPU 계산과 같은 값을 내는 것을 테스트로 확인했다(`test_to_input_matches_the_old_cpu_calculation`).

| 돌린 곳 | 코드 | 한 건 읽기 | 한 걸음 (`bisenet`, 1024, 묶음 4) | 1에폭 학습 | 1에폭 손실·검증 평균 |
