# 필수 정보 Gemini 추출 시험

2026-11-03 · S15P31A306-278

쉬운 설명에 꼭 있어야 할 정보(바르는 곳, 팔레트에서 고르는 색)를 Gemini가 영상에서 뽑을 수 있는지 봤다.

## 필수로 고른 기준

세 가지를 모두 만족하면 필수다.

1. 없으면 거울 앞에서 따라 할 수 없다 (시작을 못 하거나 다른 곳·다른 색에 바른다)
2. 그런 단계라면 영상에 항상 나온다 (아니면 멀쩡한 요청이 거절된다)
3. 화면의 다른 곳이 대신 보여 주지 않는다 (제품 이름·호수는 제품 카드에 나온다)

| 정보 | ① 따라 하는 데 필요 | ② 영상에 항상 있음 | ③ 대신 보여 주는 곳 | 결론 |
|---|---|---|---|---|
| 바르는 곳 | 그렇다 | 바르는 동작마다 있다 | 얼굴 가이드라인. 5종만 되고 화장 종류 분류가 불안정하다 | 필수 |
| 팔레트에서 고르는 색 | 그렇다 | 팔레트 단계면 있다 | 없다. 호수는 팔레트 전체 이름이다 | 팔레트 단계만 필수 |
| 도구 | 약하다 | 거의 늘 채워진다 | 없다 | 선택 |
| 양 · 세기 · 끝 기준 | 있으면 좋다 | 18단계 중 0~4개 | 없다 | 선택 |
| 제품 이름 · 호수 | 아니다 | 그렇다 | 제품 카드 | 선택. 호수는 설명에 써도 된다 |

근거

- 같은 영상의 예전 Gemini 실행 4회: `summary`에 바르는 곳이 없는 단계가 회차마다 0·3·4·0개. 크림 블러셔 "먼저 얹어준다"는 어디에 바르는지 알 수 없었다. 팔레트 단계 12번 중 고른 색이 나온 건 9번
- 이미지 비교 실행(S15P31A306-277, 설명 114개): 빠짐 판정 16건 중 7건이 팔레트 색
- 화장 종류(`makeup`)는 18단계 중 7개가 `other`이고 실행마다 바뀐다. 그래서 단계 종류는 화장 종류가 아니라 팔레트인지로 나눈다

## 한계

- 한 단계에 여러 자리·여러 색이 섞이면 칸 하나로 담기 어렵다. 「바르는 자리가 바뀌면 단계 나누기」 요청(김현수 → 김정윤)이 풀리면 줄어든다.

## 결정 (11.03)

- 가이드 입력 v2: `facts.area` 필수, 제품이 있으면 `product.palette` 필수 (팔레트면 `{color}`, 아니면 `null`)
- 한 가지 색 제품의 호수는 `product.shade`에 남기고, 설명을 만드는 Claude에게는 보내지 않는다
- 호수는 설명에 써도 된다. 팔레트에서 고른 색이 호수 이름일 때가 있다 (예: 호수 "핑크뮬리", 고른 색 "핑크뮬리, 플랫피치")
- 바르는 곳·팔레트 색을 근거로 단 설명 문장이 없으면 확인 실패(`required_unused`)로 남긴다
- BE의 Gemini 출력 형식은 2차 형식을 제안한다

## 재현 방법

`ai/` 폴더에서 실행한다. `.env`에 `GEMINI_API_KEY`가 있어야 한다. 무료 키는 분당 25만 토큰이라 영상 하나(약 15만 토큰)씩 1분 간격으로 돌린다.

```bash
uv run python tools/gemini_video_test.py run "https://www.youtube.com/watch?v=<영상 ID>"   # 결과 → tools/gemini_runs/<영상 ID>_<회차>.json
```

| 결과 파일 (`ai/tools/gemini_runs/`) | 형식 |
|---|---|
| `eFzG30avtOI_5~7`, `BJOEa0LjLYw_1~3`, `OubRDaaWGPc_1~3` | 1차 |
| `eFzG30avtOI_8`, `BJOEa0LjLYw_4`, `OubRDaaWGPc_4` | 2차 (지금 `gemini_prompt.txt`·`SCHEMA`) |

파일마다 그때의 지시문(`prompt`)과 형식(`schema`)이 함께 들어 있다.
