# 단계 끝 안내 문장: 덮음 0.2 · 방향 덮음 0.03 · 넘침 먼저 · 덜 바름 쪽 넘침은 0.4부터 · 진하기는 게이지 여유까지

단계 끝 AI 평가(덮음 · 넘침 · 진하기, [GAUGE_STEP_EVALUATION.md](GAUGE_STEP_EVALUATION.md))를 사용자가 읽을 안내 문장으로 바꾸는 규칙이다. 숫자 · 점수 · 합격 · 「잘했어요 / 실패」는 보이지 않고, 진하기는 게이지와 같은 「레퍼런스보다 연해요 / 비슷해요 / 진해요」만 쓴다. 문장과 평가 결과는 기록에 남기지 않는다.

## 요약

- **문장은 일곱 가지다.** 덜 바름(「블러셔를 조금 더 발라 주세요」), 넘침(「섀도는 가이드보다 눈꼬리 쪽으로 넓게 발랐어요」), 빈 쪽(「립 아래쪽에도 발라 주세요」), 진해요 · 연해요 · 비슷해요, 못 봄(「손이나 도구가 가려서 블러셔는 확인하지 못했어요」). 좌우 짝에서 한쪽만이면 「왼쪽 · 오른쪽」을 붙인다. 문장에는 부위 대신 화장 이름(섀도 · 블러셔 · 쉐딩 …)을 쓴다. FE가 같은 부위 단계를 카테고리로 묶어(눈 · 눈썹 · 볼 · 입술) 볼 묶음에 블러셔 · 쉐딩 · 하이라이트가 섞이기 때문이다.
- **기준값을 444 첫 값에서 바꿨다.** 덮음 0.4 → 0.2, 방향 덮음 0.1 → 0.03, 방향 넘침 0.3은 그대로다. 합성 · 레퍼런스 영상의 「맞힘 − 틀림」 세 가지를 같은 무게로 더한 값이 1.384에서 1.570으로 올랐다. 꽉 바른 합성에서 잘못 지적하는 몫이 0.271에서 0.175로, 레퍼런스 본인에게 영역 잔소리가 나오는 몫이 0.538에서 0.462로 줄었다. 대신 바르지 않은 영역에 「조금 더」가 나오는 몫이 0.955에서 0.910으로 줄었다.
- **좌우 짝은 쪽마다 따로 본다.** 합쳐 보는 것보다 레퍼런스 영상에서 영역을 옮긴 경우 방향을 맞히는 몫이 0.614에서 0.682로 높았다. FE 결과 형식의 `regions`에 방향별 `sides`를 더해야 한다.
- **덜 바름을 말한 쪽의 넘침은 그쪽 전체 넘침이 0.4 이상일 때만 말한다.** 시연자 섀도 영상(4분)에서 바르지 않은 립 · 블러셔에 「립은 가이드보다 입꼬리 쪽으로 넓게 발랐어요」가 20곳 중 13곳 나왔다. 조명 변화(맨피부 6.1)와 입 모양 탓이다. 이 규칙으로 1곳이 됐다. 영역을 옮겨 바른 경우의 방향 맞힘은 줄었다(레퍼런스 0.682 → 0.485). 네 자료를 같은 무게로 더한 값이 0.4에서 가장 컸다.
- **한 하위 단계 안에서는 덜 바름 → 넘침 → 빈 쪽 → 진해요 → 연해요 → 못 봄 → 비슷해요 순서로 2문장까지 남긴다.** 넘침을 빈 쪽보다 앞에 두면 첫 문장이 맞는 몫이 0.699에서 0.706으로 조금 올랐다. 2문장이면 3문장일 때 맞힘(0.770)의 거의 다(0.757)를 담는다.
- **묶음 끝에는 하위 단계마다 첫 문장을 먼저 놓고 3문장까지 보인다.** 글자가 같은 문장은 한 번만 넣는다. 종류 순서로 고르는 것보다 하위 단계마다 한 줄씩 들어가는 몫이 높았다(0.739 대 0.662).
- **진하기는 게이지 경계(0.837 · 1.183)를 게이지가 문구를 바꿀 때와 같은 여유 10%만큼 넘어야 「연해요 · 진해요」다.** 여유가 없으면 꽉 바른 합성의 35%에 「연해요 · 진해요」가 나왔다. 10%면 9%다. 덜 바름을 말했으면 「연해요」는 같은 말이라 뺀다. 「비슷해요」는 영역 문장이 없을 때만 낸다.
- **말하지 않는 경우**: 아이라인(평가 안 함)은 이유와 상관없이 말하지 않는다. 444가 시작 칸 색이 없으면 아이라인에도 `noStart`를 먼저 내서 「얼굴이 잘 보이지 않아서 아이라인은…」이 나오던 것을 막았다. 기본 가이드 단계(`noArea`)와 영역이 칸보다 작음(`tooFewCells`)도 사용자가 바꿀 수 없어 말하지 않는다. 가림 · 조명 바뀜 · 얼굴이 안 보임은 이유를 말한다.

「고칠 것 맞힘」은 없음 · 한쪽만 · 비움 · 밀림 · 번짐(양 1)의 맞힘 평균이다. 후보를 고르는 값은 세 자료의 「맞힘 − 틀림」을 같은 무게로 더한 것이다: (합성 고칠 것 맞힘 − 꽉 바름 영역 틀림) + (레퍼런스 shifted 맞힘 − 틀림) + (레퍼런스 control 「조금 더」 − own 영역 잔소리). 시연자 자료가 판단을 바꾼 마지막 규칙에서는 시연자 점수(1 − 바르지 않은 립 · 블러셔의 넘침 몫)를 하나 더 더했다.

## 넘길 것 · 한계

- **기능명세와 어긋남.** 기능명세 GUIDE-013은 「단계 끝 확인 창은 사진 확인 용도로만, 진하기 판정 문구 없음」 「미포함: 자동 합격 · 자동 단계 이동 · 도포 채점」이고, 제외 기능에 「도포 영역 자동 채점 · 종합 AI 평가」, 유저플로우 변경 요약에 「채점 · 영역 판정 제외」가 있다. 10-19 ADR-007은 단계 끝 1회 판정 · 규칙 문장 · 실행 기록 저장이다. 이 규칙은 점수 · 합격 · 판정 낱말 없이 안내 문장만 내고 기록에 남기지 않는다. FE는 단계 끝 확인 창 없이 묶음 끝에 사진만 찍으므로 문장은 확인 창이 아닌 묶음 끝 안내에 보인다. 그래서 기능명세(GUIDE-013 완료 기준 · 기능 설명 · 주요 정책, GUIDE-006, 제외 기능, 확인 필요 8)와 유저플로우(튜토리얼 단계 넘기기, 변경 요약)를 이 작업에서 「판정 없는 안내 문장 · 묶음 끝 최대 3줄 · 기록 안 남김」으로 같이 고쳤다. 바뀐 곳 표는 FE 요청 문서 7번에 있다.
- **립 진하기 비율이 높게 재진다**(꽉 바른 합성 립 중앙 1.16 · p90 1.35). 여유 10%로 「진해요」는 거의 막았지만, 진하기 계산(S15P31A306-440 · 441)에서 원인을 볼 일이다.
- 시연자 섀도처럼 레퍼런스 효과가 작은 섀도는 바른 칸이 문턱 3에 덜 걸려 「조금 더」가 나오기 쉽다. 기준값은 설정 자동 탐색(S15P31A306-446)과 실기기 녹화(S15P31A306-447)에서 다시 고른다.
- 「얼굴이 잘 보이지 않아서 … 확인하지 못했어요」(`noStart` · `noEnd`)가 실제로 얼마나 자주 나올지는 「다음」을 누르는 실제 흐름에서 재야 한다.
- 문장 낱말(화장 이름 · 방향 낱말 · 「발라 / 채워 / 그렸어요」)은 FE 화면에서 읽어 보고 고칠 수 있다. 규격 파일의 `texts` · `parts` · `sideWords`만 바꾸면 된다.
