# 레퍼런스와 사용자 캠의 색감 맞추기: 흰자 기준 혼합 모델 · 자리마다 비율

레퍼런스 영상(링라이트 · 뷰티 필터 · 영상 압축)과 사용자 캠(방 조명 · 태블릿 자동 노출)은 같은 화장도 다른 색으로 찍힌다. 「레퍼런스보다 연해요 / 비슷해요 / 진해요」를 말하려면 두 화면의 화장을 같은 기준으로 견줘야 한다. 그 방법을 합성 시험 세트와 시연자 실제 사진으로 견줘 고른 기록이다. 레퍼런스 쪽 효과는 [GAUGE_MAKEUP_EFFECT_SCALE.md](GAUGE_MAKEUP_EFFECT_SCALE.md), 사용자 캠 쪽 기준은 [GAUGE_BARE_FACE_BASELINE.md](GAUGE_BARE_FACE_BASELINE.md)가 각자 화면 안의 조명 변화를 뺀다. 이 문서는 두 화면 사이의 차이를 다룬다.

같은 화장은 **같은 제품을 같은 양 바른 것**으로 정했다. 피부톤이 달라도 같은 양이면 「비슷해요」가 맞다. 어두운 피부에서 같은 양이 눈에 다르게 보인다고 「연해요」라고 하면, 더 바르라는 틀린 안내가 된다.

## 요약

- **맞추지 않으면 쓸 수 없다.** 같은 화장인데 조명 · 카메라만 달라도 ΔE2000 가운데 5.49, 피부톤까지 다르면 13.66으로 읽혔다. 진하기 비율은 1.84배 · 3.92배였다.
- **Jira에 적힌 방법 B(맨피부로 맞춘 뒤 바른 색끼리 비교)는 6.59로 나쁘다.** 두 사람 입술 · 눈썹 원래 색 차이까지 화장 차이로 읽는다. 각자 바르기 전 → 바른 뒤 효과를 견주는 방법(A · C · 자리마다 비율)은 조명만 다를 때 0.8~0.9까지 줄인다.
- **맨피부만으로는 「조명이 어두운 것」과 「피부가 어두운 것」을 가를 수 없다.** 합성에 쓴 피부톤 변화의 색 방향은 색온도 변화와 3.5~6도밖에 차이 나지 않고, 밝기는 둘 다 어두워진다. 그래서 바르기 전 색 · 맨피부의 차이를 모두 조명으로 보고 맞추는 방법(local)은 가장 어두운 피부에서 같은 양을 1.62배로 읽었다.
- **흰자는 피부톤과 상관없이 거의 흰색이라 조명 · 카메라 차이만 담는다.** 흰자 비율로 조명을 맞추고, 혼합 모델(바른 뒤 색 = (1 − 양) × 바르기 전 색 + 양 × 안료 색)로 레퍼런스와 같은 양을 사용자 얼굴에 칠한 목표 색을 만든다. 피부톤만 다를 때 1.27(바르기 전 색 비율을 옮기는 local 2.16), 진하기 1.01배(0.59~1.28배)로 읽었다. 조명만 다를 때는 local과 같이 0.20이었다.
- **부위별로 고른다.** 립 · 블러셔 · 아이섀도 · 쉐딩 · 하이라이트는 흰자 기준 혼합 모델(`COLOR_METHOD`)이다. 눈썹 · 아이라인은 자리마다 비율(`DARK_METHOD`)이다. 검정 · 갈색 화장은 합성에서 둘이 거의 같았고, 시연자 실제 사진에서 눈썹이 1.96 대 2.58로 자리마다 비율이 버텼다.
- **흰자는 맨얼굴 기준 사진에서 잰다.** 화장한 뒤에는 아이라인 · 속눈썹이 흰자 둘레를 덮어 R이 161에서 123으로 어둡게 읽혔다. 화장 뒤 사진으로 재면 시연자 립이 같은 화장인데 1.38배 · 0.65배로 틀렸다.
- **고른 방법을 합친 결과**: 조명 · 카메라만 다를 때 0.84(맞추기 전 5.49), 피부톤만 다를 때 1.27(9.77), 피부톤과 조명이 같이 다를 때 1.82(14.84)다. 시연자를 카메라 앱과 태블릿으로 찍은 같은 화장은 1.84(2.48), 진하기 1.01배(0.64~1.59배)였다.
- **고칠 수 없는 것**: 사진 값을 휘게 하는 카메라 처리(뷰티 필터 · 쨍한 대비 · 납작한 곡선)는 어떤 방법으로도 0.72~1.30배가 남는다. 레퍼런스에 뷰티 필터가 걸리면 사용자 쪽이 1.33배 진하게 읽힌다. 레퍼런스 효과가 아주 작은 단계(시연 영상 눈 뜬 섀도 1.7)는 진하기 비율이 7~18배로 튄다.

## 용어

| 용어 | 뜻 |
| --- | --- |
| 선형 RGB | 사진 값(0~255)의 감마를 푼 값. 빛 세기에 비례해서 조명은 여기서 채널마다 곱하기가 된다 |
| 색순응 변환 | 기준으로 삼은 색(흰 종이 · 맨피부 · 흰자)이 같아지도록 채널마다 배수를 곱하는 것. 카메라 화이트밸런스와 같은 일이다 |
| 혼합 모델 | 바른 뒤 색 = (1 − 양) × 바르기 전 색 + 양 × 안료 색. 양은 안료가 피부를 덮은 비율(0~1)이다 |
| 가장 적게 바른 양 (`least_paint`) | 안료 색은 채널마다 0(검정)~1(흰색) 안에 있어야 하므로, 레퍼런스에서 본 변화를 만들려면 적어도 이만큼은 발랐어야 하는 양 |
| 목표 색 | 레퍼런스와 같은 안료를 같은 양만큼 사용자 바르기 전 색에 칠했을 때의 색. 사용자 조명으로 옮긴 안료를 쓴다 |
| 진하기 비율 | 바탕(사용자 바르기 전 색)에서 잰 「사용자 바른 뒤 색까지 ΔE2000 ÷ 목표 색까지 ΔE2000」. 1이면 레퍼런스와 같은 양이다 |

## 방법

`ai/tools/gauge/color_match.py`의 `compare(reference, user, method)`가 두 화면의 영역(`AreaSide`: 바르기 전 색 · 바른 뒤 색 · 맨피부 색 · 흰자 색, 모두 선형 RGB)을 받아 한 바탕 위에 두 화장을 올리고 ΔE2000으로 견준다.

| 후보 (`MatchMethod.name`) | 하는 일 | Jira 본문 |
| --- | --- | --- |
| `none` | 바른 뒤 색끼리 본다 | 맞추기 전 |
| `effect` | 각자 같은 칸의 바르기 전 → 바른 뒤 Lab 차이를 한 바탕 위에 얹는다 | 방법 A(둘레 맨피부 대신 같은 칸 전후. 둘레 맨피부는 [GAUGE_MAKEUP_EFFECT_SCALE.md](GAUGE_MAKEUP_EFFECT_SCALE.md)에서 떨어짐) |
| `skin` | 각자 기준 색을 공통 기준으로 옮기는 색순응 변환을 바른 색에 적용해 바른 뒤 색끼리 본다 | 방법 B |
| `skinEffect` | `skin`으로 옮긴 공간에서 `effect`처럼 효과끼리 본다 | 방법 C |
| `local` | 각자 같은 칸의 바른 뒤 ÷ 바르기 전 비율을 한 바탕 색에 곱한다. 그 자리 바르기 전 색을 흰 종이 삼은 색순응 변환이다 | 추가 |
| `mix` | 혼합 모델로 레퍼런스 안료와 가장 적게 바른 양을 거꾸로 구해, 안료를 (사용자 기준 색 ÷ 레퍼런스 기준 색)^weight 배 옮긴 뒤 사용자 바르기 전 색에 같은 양을 칠한 목표 색과 사용자 바른 뒤 색을 견준다 | 추가 |

후보마다 곱한 축이다(`all_methods`, `compare_color_match.method_runs`, 250가지).

| 축 | 값 | 쓰는 후보 |
| --- | --- | --- |
| 기준 색 (`anchor`) | 맨피부 / 흰자 | `skin` · `skinEffect` · `mix` |
| 맨피부 재는 곳 | 바르는 곳 둘레를 뺀 얼굴 피부 전체 / 이마 · 턱 / 영역 둘레 띠 | 맨피부 기준일 때 |
| 배수를 곱하는 축 (`space`) | 선형 RGB / Bradford / CAT16 | `skin` · `skinEffect` · `local` |
| 얼마나 맞추나 (`degree`) | 밝기까지 / 색만(밝기는 그대로) / 배수의 제곱근 | `skin` · `skinEffect` |
| 바탕 (`target`) | 레퍼런스 쪽 / 사용자 쪽 / 둘의 기하 평균 | `effect` · `skin` · `skinEffect` · `local` |
| 기준 색 차이를 조명으로 보는 정도 (`weight`) | 1 / 0.5 / 0 | `mix` · `local`(선형 RGB) |
| 비율을 내는 법 | 영역 색끼리 나눈 비율 / 칸마다 비율의 가운데 값 | `local`(선형 RGB) |

흰자 색(`white_color`)은 맨얼굴 지도의 두 눈 구멍 픽셀 중 밝기 위 25%이고, 채널 하나라도 250 이상인 반사광은 뺀 픽셀의 가운데 값이다.

## 시험 재료

| 재료 | 내용 | 무엇을 보나 |
| --- | --- | --- |
| 합성 시험 세트 (`ai/tools/gauge/compare_color_match.py`) | 맨얼굴 지도 두 장(시연자 태블릿 맨얼굴 영상 첫 좋은 사진 15장, GO지승 파운데이션 직전 3초 13장)에 화장 10모양(립 3 · 블러셔 · 섀도 2 · 아이라인 · 눈썹 · 쉐딩 · 하이라이트) × 안료 2색 × 진하기 0.25 · 0.5를 칠함. 사용자 쪽은 같은 안료를 0.5 · 0.7 · 1 · 1.4 · 2배, 또는 1배에서 색상만 ±25도 돌려 칠함. 레퍼런스 조건 4(얼굴 2 × 그대로 · 뷰티 필터), 사용자 조건 104(얼굴 2 × 조명 18 · 카메라 처리 7 · 피부톤 3 · 섞은 조건 24). 장면 쌍 116,480개 | 정답을 아는 같은 화장 · 다른 양 · 다른 색 |
| 카메라 앱 ↔ 태블릿 | 시연자 같은 날 같은 강의실. 카메라 앱은 맨얼굴 사진 1장 → 화장 뒤 정면 2장, 태블릿은 맨얼굴 영상 15장 → 섀도 바르는 영상(4분) 끝 15장. 부위 7곳 × 두 방향 | 같은 사람 · 같은 화장을 다른 카메라로 찍은 실제 쌍. 0 · 1배가 정답이다 |
| 시연 레퍼런스 ↔ 시연자 태블릿 | RBm4 립 · 섀도 단계 직전 · 직후 3초, 시연자 태블릿 립(맨얼굴 → 끝)과 섀도(섀도 영상 처음 → 끝) | 정답이 없어 그림과 진하기 비율만 본다 |

합성 장면 쌍은 피부(얼굴 · 피부톤)와 찍는 조건(조명 · 카메라)이 같은지로 나눴다: 조명 · 카메라만 다름(40,320쌍), 피부만 다름(4,480쌍), 둘 다 다름(70,560쌍). 피부만 다름 중 얼굴이 바뀐 쌍(시연자 ↔ GO지승)은 두 지도가 실제로 다른 카메라로 찍혀 있어 피부 차이와 카메라 차이가 섞인다. 그래서 고를 때는 같은 얼굴에 피부톤만 바꾼 쌍과 피부톤 + 조명 · 카메라 쌍을 따로 봤다. 합성 피부톤은 선형 RGB에 밝게(1.12, 1.18, 1.25) · 어둡게(0.62, 0.5, 0.42) · 가장 어둡게(0.4, 0.28, 0.2)를 곱했고, 눈 구멍(흰자 · 눈동자)은 바꾸지 않았다.

얼굴 사진 · 지도는 저장소에 넣지 않았다. 시험 코드(`ai/tests/test_gauge_color_match.py`)는 평평한 색으로 같은 규칙을 확인한다.

## 점수

사람이 고른 숫자 없이 아래로 견줬다.

- **같은 화장 오차**: 같은 안료 · 같은 양(1배) 쌍의 두 화장 ΔE2000 가운데 값과 90%. 0이어야 한다.
- **같은 화장 진하기 비율**: 같은 화장 쌍에서 읽힌 진하기 비율의 10% · 가운데 · 90%. 1이어야 한다.
- **진하기 비율 오차**: 같은 안료 쌍 전부에서 |log2(읽힌 비율 ÷ 실제 배수)| 가운데 값. 0.5면 √2배쯤 틀린다.
- **구간 맞힘**: 실제 배수 0.5 · 0.7은 「연해요」, 1은 「비슷해요」, 1.4 · 2는 「진해요」가 맞다고 두고, 읽힌 비율을 이웃 배수의 기하 평균(0.837 · 1.183)에서 나눠 맞힌 비율. 경계는 시험 배수에서 나온 것이고, 실제 경계는 실기기 녹화로 따로 정한다.

## 한계

- 실제 「같은 화장 · 다른 카메라」는 시연자 한 사람 · 한 강의실 · 카메라 두 개다. 피부톤이 다른 실제 사람은 없어 피부톤 판단은 합성으로만 했다.
- 합성 피부톤은 선형 RGB 배수 하나라서 실제 피부(멜라닌 · 헤모글로빈 · 피지 광택)보다 단순하다. 흰자도 사람마다 조금 누렇거나 붉을 수 있다(나이 · 충혈).
- 혼합 모델의 안료는 가장 적게 바른 양으로 푼 것이라 실제 안료와 다를 수 있다. 제품 색(호수 색)을 알면 더 정확해질 수 있다. 대체 제품 작업에서 같이 본다.
- 색감(색상) 차이는 같은 화장 오차로만 봤다(색상 ±25도 안료를 가르는 정도: 조명 · 카메라만 0.77, 피부톤 0.59~0.69). 색상 각도로 「주황빛 · 붉음」을 말하는 규칙은 맞춘 색으로 진하기 · 색감을 재는 작업에서 정한다.

## 다시 돌리기

```bash
cd ai
uv run pytest tests/test_gauge_color_match.py
uv run python tools/gauge/compare_color_match.py <결과 폴더> --face go=<맨얼굴 지도.png> --face seoyeon=<맨얼굴 지도.png> --workers 6
uv run python tools/gauge/compare_color_match.py <결과 폴더> --rows <결과 폴더>/rows.npz
```

맨얼굴 지도는 `shared/face-mesh`로 편 256 × 256 PNG다. 첫 줄은 장면을 찍고 점수를 내고(6코어 노트북 5분쯤), 둘째 줄은 저장한 장면으로 점수만 다시 낸다. 카메라 앱 ↔ 태블릿과 레퍼런스 ↔ 시연자 비교는 시연자 영상 · 사진을 읽어서 저장소에 넣지 않았다. 같은 비교를 하려면 얼굴 지도를 438 기준 방식(`baseline.grid_lab` · `build_baseline` · `light_change`)으로 잰 뒤 `color_match.compare`에 넘긴다.
