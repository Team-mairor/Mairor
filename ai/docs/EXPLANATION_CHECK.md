# 설명 확인 기준

Claude가 만든 단계 설명이 입력에 근거하는지 단계마다 확인한다. 코드는 `app/tasks/explanation/explanation_checker.py`, 지시문은 `app/prompts/explanation_check.txt`다.

## 코드 검사

| 종류 | 걸리는 경우 |
|---|---|
| `no_source` | 문장에 근거 번호가 없음 |
| `unknown_source` | 근거 번호가 입력에 없는 번호 (예: 입력에 없는 `c1`) |
| `number` | 문장의 숫자가 입력 글에 없음 |
| `product_name` | 제품·브랜드 이름(2자 이상)이 문장에 들어감. 띄어쓰기는 무시. 호수는 팔레트 색 이름일 때가 있어 보지 않음 |
| `too_long` | 동작 25자, 팁·넘어갈 때 30자를 넘음. 끝 마침표는 세지 않음 |
| `direction` | "A에서 B로"가 입력의 "B에서 A로"와 반대. 입력에 두 방향이 다 있으면 걸리지 않음 |

## Claude 검사

문장마다 근거가 된 입력의 말을 먼저 옮겨 적고 판정한다. 이미지는 보내지 않는다.

| 종류 | 걸리는 경우 |
|---|---|
| `not_in_input` | 입력에 없는 동작·양·횟수·시간·숫자·방향·위치·도구·바르는 방식, 입력에 없는 준비 동작 |
| `meaning_changed` | 입력을 뒤집음, 방향·순서가 반대, 제품 효과를 사용자 동작으로 바꿈, 크리에이터 자기 얘기를 안내로 바꿈 |
| `not_action` | 할 일이나 확인할 것이 아니라 이유·결과·제품 효과만 말함 |
| `hard_word` | 처음 하는 사람이 모를 말. 알림만 하고 통과는 막지 않는다. 입력에 뜻이 없어 다시 만들어도 채울 수 없어서다 |
| `omitted` | 입력의 할 일(동작·바르는 방식·위치·양·숫자·멈출 때, 팔레트에서 고르는 색)이 설명 어디에도 없음. 문장 번호 대신 입력 번호로 남는다 |

- Claude 답에 없는 문장은 `unchecked`로 남긴다. `hard_word`처럼 알림만 하고 통과는 막지 않는다. 문제없는 문장과 확인이 안 된 문장을 기록에서 따로 보기 위해서다.
- 통과는 `hard_word` · `unchecked` 말고는 걸린 것이 없다는 뜻이다.
- 빠진 것은 문장 판정을 다 한 뒤에 찾는다. 이유·효과, 크리에이터 얘기, 이름, 바꾸지 않는 도구, 다른 줄에서 이미 들어간 내용은 빠져도 된다.

## 결과

- 지금은 기록(`check_step` span, 로그)만 남기고 설명은 그대로 보낸다. 걸렸을 때 다시 만들기와 기본 문장은 S15P31A306-253에서 한다.
- 확인 호출이 실패해도(`LlmError`) 작업은 실패하지 않는다. `check_step`에 "확인하지 못함: 이유"로 오류를 남기고 설명은 그대로 보낸다.
