# 얼굴 데이터 좌표 규칙

얼굴 추적(FE)과 레퍼런스 분석(AI)이 같이 따르는 좌표·좌우·크기 규칙이다. 파일 목록과 메시 규칙은 [README](README.md), 부위 점 번호는 `regions.v1.json`, 타입은 `frontend/src/features/face/types.ts`가 기준이다.

## 공통 규칙

| 항목           | 규칙                                                                                                                           | 이유                                                            |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------- |
| 좌표           | 반전 전 원본 프레임 기준 정규화 좌표 0~1. 원점은 왼쪽 위, x는 오른쪽, y는 아래로 증가. z는 상대 깊이(작을수록 카메라에 가까움) | 해상도·기기가 달라도 같은 값. 픽셀 변환은 그릴 때만 한다        |
| 좌우           | 사용자 신체 기준. `leftEye`는 사용자의 실제 왼쪽 눈이고 원본 프레임에서는 오른쪽(x > 0.5)에 있다. 데이터는 반전하지 않는다     | 데이터와 화면을 둘 다 뒤집으면 두 번 반전된다                   |
| 거리·각도 계산 | 정규화 좌표를 픽셀 좌표로 바꾼 뒤 계산한다 (X = x × 너비, Y = y × 높이)                                                        | 정규화 좌표는 가로·세로 단위가 달라 길이와 각도가 틀어진다      |
| 크기 단위      | 두 홍채 중심(468, 473) 사이 거리(IOD) = 1 기준 비율. `feather`·`width`·부위 크기에 쓴다                                        | 카메라와의 거리가 달라도 같은 얼굴은 같은 값이다                |
| 각도           | 라디안, 픽셀 좌표 기준 `atan2(dy, dx)`. 축은 `regions.v1.json`의 `axis` [시작, 끝]                                             | 좌우 부위를 같은 규칙으로 비교한다                              |
| 얼굴 방향      | 사용자 왼쪽으로 돌리면 yaw +, 위를 보면 pitch +, 왼쪽으로 기울이면 roll +                                                      | FE 추적기(`face/tracker.ts`)가 변환 행렬에서 이 부호로 계산한다 |
| 화장 위치      | 얼굴 메시 삼각형 번호 + 무게중심 비율(`MeshAnchor`)                                                                            | 다른 얼굴·표정·각도에서도 같은 부위에 맞춰진다                  |

## 화면 변환

원본 좌표를 화면에 그릴 때는 이 변환 하나만 쓴다 (FE `toScreen`). 거울 반전은 여기서 한 번만 한다.

```txt
x' = mirrored ? 1 − x : x
화면X = x' × 원본너비 × scale + offsetX
화면Y = y  × 원본높이 × scale + offsetY
크기(화면 px) = 값(IOD 기준) × iod(원본 px) × scale
```

- FE는 영상 전체를 화면 안에 넣는다(contain). `scale` = min(화면너비 / 원본너비, 화면높이 / 원본높이), 남는 쪽은 가운데 정렬한다
- 예: 원본 640×480, 화면 800×1280, 거울 모드 → `scale` 1.25, `offset` (0, 340). `leftEye` 바깥 꼬리 263번 (0.62, 0.40)은 x' = 0.38이 되어 화면 (304, 580), 화면 왼쪽 절반에 보인다
- 자주 하는 실수: 정규화 좌표로 바로 거리·각도를 계산한다, 영상을 CSS로 반전하고 좌표도 반전한다, 크기를 화면 픽셀로 저장한다

## MeshAnchor

```txt
위치 = bary[0] × 꼭짓점A + bary[1] × 꼭짓점B + bary[2] × 꼭짓점C
```

- 삼각형 번호는 `triangles.v1.json`의 배열 위치, 꼭짓점은 지금 프레임의 랜드마크다
- `bary` 합은 1이어야 한다. 허용 오차는 FE(`overlay/mesh.ts`) 0.001, AI(`schemas/guide_area.py`) 0.01로 다르다
- 아이라인 꼬리·오버립처럼 삼각형 밖에 걸치는 점은 가장 가까운 삼각형 기준으로 계산하고 음수를 허용한다
- 데이터에는 어느 번호표 기준인지 `meshVersion`으로 적는다

## 얼굴 하나만 추적

- MediaPipe는 `numFaces: 1`로 한 얼굴만 추적한다. `numFaces: 2`는 갤럭시탭에서 FPS가 절반으로 떨어진다
- 1.5초마다 얼굴 검출기(BlazeFace)로 가장 큰 얼굴을 확인하고, 추적 중인 얼굴이 아니면 그 얼굴을 다시 잡는다. 얼굴을 놓쳤다 다시 잡은 뒤 3초 동안은 0.5초마다 확인한다
- 손에 가려 지금 얼굴이 작게 잡히는 사이 뒤 사람으로 넘어가지 않도록, 다른 얼굴이 1.5배 이상 크고 연달아 2번 확인될 때만 바꾼다

## 정하지 않은 것

- 눈 상태에 따른 가이드 표시(눈을 감으면 아이섀도 영역 전체, 뜨면 흐리게)는 구현하지 않았다. MediaPipe에는 쌍꺼풀 접히는 선을 나타내는 점이 없어, 눈을 뜬 상태에서는 접혀 안 보이는 피부 위에도 섀도 가이드가 그려질 수 있다
