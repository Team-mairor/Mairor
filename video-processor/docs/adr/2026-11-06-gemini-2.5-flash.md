# ADR: 영상 전처리 GMS 모델로 Gemini 2.5 Flash 채택

- 상태: 채택 확정
- 결정일: 2026-11-06
- 적용 범위: 영상 전처리의 오디오 관측 추출 및 OCR/CV 관측 관계 검증
- 채택 모델: `gemini-2.5-flash`
- 관련 작업: `feat/subtitle-step-S15P31A306-352`

## 배경

메이크업 영상에서 제품과 사용 목적의 고정 분류를 기준으로 단계를 구성한다. 오디오에서 곧바로 최종 단계를 생성하면 제품명 생략, 세부 부위 변경, 도포와 블렌딩의 차이 때문에 같은 작업이 여러 단계로 나뉠 수 있다.

따라서 GMS는 시간·제품·부위·행동·원문 근거가 포함된 관측을 촘촘하게 추출한다. 이후 코드가 인접 관측의 연속 사용과 전환 경계를 검사하고, 불확실한 관계는 이웃 문맥과 영상 OCR/CV로 검증한다. 실제 단계의 병합·분리와 확정 여부는 이 근거를 바탕으로 코드가 결정한다.

이 파이프라인의 기본 모델을 결정하기 위해 Gemini 2.5 Flash, 3.5 Flash, 3.8 Flash를 검토했다.

## 결정

오디오 관측 추출과 영상 OCR/CV 관계 검증의 기본 모델을 모두 `gemini-2.5-flash`로 고정한다. 두 단계에 동일한 선택 모델을 전달하고 요청 모델 및 실제 응답 버전을 기록한다.

이번 결정은 현재 구현과 실측을 기준으로 운영 기준 모델을 정한 것이다. 세 모델의 전체 영상 정확도와 처리 속도 우열이 최종 입증됐다는 의미는 아니다. 사용자 결정에 따라 나머지 모델의 전체 비교 실행은 중단했다.

## 채택 근거

### 1. 같은 이미지 검증 입력에서 낮은 입력 토큰과 짧은 응답 시간을 관측했다

동일 프롬프트·스키마·원본 이미지 3장을 사용한 GMS 요청의 측정값은 다음과 같다. 세 요청의 본문 크기는 모두 300,807바이트이고 SHA-256도 동일하다.

| 요청 모델 | 실제 응답 버전 | 응답 시간 | 입력 토큰 | 이미지 입력 토큰 | 출력 토큰 |
|---|---|---:|---:|---:|---:|
| Gemini 2.5 Flash | gemini-2.5-flash | 2.23초 | 1,454 | 774 | 113 |
| Gemini 3.5 Flash | gemini-3.6-flash | 3.35초 | 3,980 | 3,300 | 198 |
| Gemini 3.8 Flash | gemini-3.8-flash | 4.28초 | 3,980 | 3,300 | 183 |

관측 관계 검증에서는 영상 이미지를 반복해서 입력하므로 이 입력 토큰 차이가 모델 선택 근거가 된다. 다만 동일 입력의 소규모 단일 실험이며, 출력 내용과 길이도 다르다. 이 측정만으로 전체 영상 속도, 정확도 또는 실제 청구 비용의 우위를 확정하지 않는다. GMS 모델별 과금 단가는 확인하지 못했으므로 통화 단위의 비용 비교는 하지 않는다.

### 2. 수정된 전체 파이프라인에서 실제 완료 경로를 확인했다

같은 30분 58초 영상에 대해 새 다운로드, 실제 GMS 호출, 관측 관계 검증, 멀티프로세스 프레임 추출, 실제 S3 프레임 및 메타데이터 업로드까지 완료했다.

- 영상 길이: 1,858.38초
- 디코딩 프로세스: 3개

다운로드·관측 추출·관계 검증·디코딩·업로드는 병행되므로 표의 시간을 합산하지 않는다. 검증·추출 구간에는 중간 대기 시간이 포함된다. S3 프레임 구간은 첫 업로드 완료부터 측정하며 첫 요청의 전송 시간은 포함하지 않는다.

| API 처리 단계 | 성공 요청 | 성공 요청 시간 합계 | 입력 토큰 | 출력 토큰 |

AI 서버 요청의 스키마 및 의미 검증, 관측 출처 보존, 미확정 단계의 프레임 추출 차단을 확인했다. S3 가이드 JSON과 첫·마지막 프레임의 HEAD 응답은 모두 200이었다.

### 3. 현재 모델을 유지하면서 단계 구성과 검증 로직을 개선한다

단계 경계는 모델의 출력만으로 확정하지 않는다. 코드가 관측 ID, 인접 관계, 제품 근거, 사용 목적, 시간 범위를 검사하고 병합·분리한다. 이 구조를 유지하면서 2.5 Flash를 기준 모델로 삼아 개선 전후의 시간·토큰·분리 결과를 일관되게 비교한다.

3.5 요청이 실제로는 3.6으로 라우팅된 사실도 확인했다. 비교할 때 요청 이름만으로 모델을 동일시하지 않고 응답의 `modelVersion`을 함께 보존한다.

## 검토한 대안

| 대안 | 확인한 점 | 이번 결정 |
|---|---|---|
| Gemini 2.5 Flash | 같은 3장 입력에서 낮은 입력 토큰과 짧은 응답 시간을 관측. 수정된 전체 파이프라인 완료 확인 | 기본 모델로 채택 |
| Gemini 3.5 Flash | 동일 입력 실험에서는 실제 3.6으로 응답. 수정 후 전체 실행은 결정에 따라 중단 | 기본 모델로 전환하지 않음 |
| Gemini 3.8 Flash | 동일 입력 실험에서 3,980 입력 토큰·4.28초. 수정 후 전체 비교는 완료하지 않음 | 기본 모델로 전환하지 않음 |

초기의 2.5 Flash 전체 시간 71.24초는 검증 101건을 로컬에서 생략한 실행의 값이다. 해당 값은 정상 처리 속도의 근거에서 제외한다. 비교 모델의 초기 결과도 검증 생략과 처리량 차이가 있어 전체 속도 순위로 사용하지 않는다.

## 수용한 한계와 남은 검증

모델 채택과 단계 분리 품질의 검증 완료는 별개다. 현재 전체 실행에는 미확정 후보 52개와 과분할 문제가 남아 있다. 오류 중심 6개 진단 조건은 2개만 통과했다. 이 수치는 전체 영상 정확도 33%를 의미하지 않으며, 채택 모델이 가장 정확하다는 근거로 쓰지 않는다.

- 마스카라, 블러셔, 두 하이라이터 구간에 분리 문제가 남아 있다. 전체 실행의 하이라이터 매칭 후보는 OFRA 6개, 무펄 하이라이터 5개였다.
- 블러셔의 기존 종료 조건에는 설명 구간이 포함될 여지가 있어 실제 도포 종료와 단계 설명 종료를 구분해 검토해야 한다. 평가 조건은 임의로 완화하지 않았다.
- 일부 구간만 검증했을 때의 개선 결과를 전체 영상 품질로 일반화하지 않는다.
- 수정된 동일 파이프라인의 3모델 전체 비교는 완료하지 않았다.
- GMS 단가를 확인하지 못했으므로 가장 저렴한 모델이라고 결론내리지 않는다.

후속 검증은 2.5 Flash를 기준으로 전체 단계의 제품 연결·과분할·누락 원인을 개선하고, 동일 영상에 대한 전체 회귀 결과를 확인하는 데 집중한다. 모델 변경은 동일 입력과 동일 파이프라인으로 처리 시간, 실제 사용량 및 구간별 정답 대조 결과를 확보한 뒤 별도 ADR로 재검토한다.

## 적용 및 운영 규칙

1. 기본 모델은 `gemini-2.5-flash`로 유지하고 오디오와 OCR/CV에 동일하게 적용한다.
2. 제품·고정 분류의 연속 관계는 코드에서 병합하고, 제품·목적·도구 작업의 전환은 별도 경계로 유지한다.
3. OCR/CV 후에도 관계가 불명확하면 미확정 후보로 보존하고 영역 분석용 프레임을 추출하지 않는다.
4. 확정 구간은 다른 구간 검증을 기다리지 않고 디코딩 프로세스 풀에 즉시 제출한다. 이미 제출한 구간을 바꾸려 하면 최종 게시를 중단한다.
5. 429는 공유 대기와 백오프·지터, Retry-After/RetryInfo를 반영해 회복을 시도한다. 120초 회복 예산을 넘기면 실행 오류로 전파한다.
6. 모델 버전, 관측별 근거, 경계별 판단 이유, 요청 시간·토큰, 재시도 및 추출·업로드 시점을 남긴다.
